1. 优先接入 VPR/Koios/Beyond-Flatland：相邻 `../../3D_FPGA_routing/` 已有 20 个 BLIF 和架构；`FPGA_Acc` 已有 attention_layer 的固定布局、RRG、连接表和完整来源记录。先选择与目标维度/架构匹配且通过源工具检查的一组完整输入，冻结源码、硬块模型、通道宽度、种子、网表/布局/RRG 哈希。不要混用不同架构下的中间文件，也不要把本地 CHANZ 改版当原版论文架构。
2. 在本目录增加 VPR 连接轨迹适配；保留规范 RR 节点、net/引脚映射、跨层边和时序/容量语义。记录连接搜索耗时、标签/候选边访问、占用与预算回退，并与同后端的基线检查合法性和质量。现有 `profile` 只读 eager RRT1，不能直接读取 BLIF/RRG/Interchange。商业 FPGA'24 的 `.phys`/DCP 留作后续验证来源，配套 exporter/runtime 仍需核对。
3. 先做串行足迹审计，再分析可并行任务。原 RRT1 合成反例已证实 bbox 检查前读取标签可跨区，但不能预设 VPR 有相同实现或竞态。若继续 RRT1 线，补查 `created`、children-cache、dead-end、occupancy 读、SLL 动态坐标；任一路线都不能凭不完整足迹宣称多 worker 无竞态。
4. 对公开应用样本比较标签私有化、静态边界预过滤或资源依赖边等具体机制，先证明与源工具结果兼容，再启用多 worker。源快照和相邻项目保持不变，方案 C 生成独立变体及结果。
5. 沿用同一搜索后端，先比较原分区、基于实际工作量的粒度调整、驻留复用等软件机制。DFMAcc 的密度补偿/容量约束可借鉴，几何独立性不能直接迁移；需要计入预处理、回退和迭代变化。
6. 预算机制遵循已实现的 [BUDGET_POLICY.md](BUDGET_POLICY.md)：默认关闭，同 CPU 重试仅作显式诊断。新后端/重调度完成后先生成包含重复搜索、调度、传输与完整墙钟的成对证据；通过输入/版本绑定和收益判据才启用。当前预算 2/8 的合成测量均未通过，不重复扫描阈值寻找偶然正收益。
7. 再按实测热点决定 FPGA 范围。当前无 GPU/FPGA 实测、传输字节、完整真实电路 routing_ms 或布后时序，不填充这些指标。
