# 方案 C 工作上下文

- 本目录研究：自适应分区与异构调度。研究问题：联合搜索工作量、驻留复用和共享资源依赖安排任务，能否提高利用率并降低完整布线时间？
- 优先阅读 README.md、EXPERIMENTS.md、INTERFACES.md、NEXT_STEPS.md。原始论文与公共参考源码位于上级目录，路径已列出。
- 当前有 Python CPU 合成调度参考，以及原始 C++ 路由器的 RRT1 插桩适配器，后者仅在合成图上验证。真实数据运行、完整性能基线、GPU 与 FPGA 实现尚未完成。不要将合成图的实测耗时、逻辑计数或排程估计解释为真实器件加速。
- 用户要求吸纳其他场景的成熟方法以提高可实现性；不能仅因方法已有基础就排除创新可能，也不能未经比较宣称新颖或保证收益。
- 当前优先任务：记录真实连接的耗时、访问足迹和预算回退，检查现有几何分区对应的共享资源。
- 2026-10-22 输入核查已纠正“没有真实输入”的旧判断：相邻 `../../3D_FPGA_routing/` 有 Beyond-Flatland 的 20 个 BLIF，`FPGA_Acc` 有 Koios/Titan 的 VPR 网表、布局、RRG、连接表及 FPGA'24 的 `.phys`/DCP。详见 `INPUT_SOURCES.md` 和 `data/input_inventory_20261022.json`。数据已定位，方案 C 适配与新实测待完成；默认 `rg --files` 会遗漏被忽略的目录，盘点数据需用 `rg --files -uuu`。
- 主线优先使用与 LaZagna/Into the Third Dimension 一致的公开电路＋研究架构，固定 packed netlist/placement/RRG 比较布线。不能将真实输入限定为 `.rrt` 或商业 DCP；不能把其他目录既有结果当作方案 C 实测，也不能把本地 CHANZ 架构适配称为原版论文架构。
- 原始参考源码保留在 `../_shared/assets/gpu_router_original/` 和 `../FPGA-Routing-main/`。本方案改写与适配放在本目录，避免无意改变其他方案的基线。若需公共改动，说明影响并运行受影响目录的检查。
- 沿用上级 AGENTS.md 的 FPGA/AMD 工具规则：按任务选择并阅读 Ross Skill；纯算法/代码/文稿任务无需启动 Vivado。实际 Vivado 操作优先检查并使用现有 MCP 会话，默认 Tcl 无 GUI；默认版本 2022.2，先核实新功能支持。
- 在已有授权内自主推进，不把实验阶段或文档中的待办项当作额外审批要求。
- 2026-10-22 实验见 `results/EXPERIMENT_20261022.md`：`python3 scripts/run.py trace-smoke` 运行 33 组合成源码检查；`python3 -m unittest discover -s tests -v` 验证审计器。公共源码保持不变；生成的 CPU 对照和插桩版都修补了原始源码 CUDA-only 清理成员未加条件编译的问题。
- 已有合成反例：包围盒不交的分区会先读候选节点的 `visited` 再判断 bbox，产生跨任务标签读写交集，最终路径仍可不共享。仅是潜在并发风险线索，未做真实器件/多 worker 数据竞争验证。
- 足迹覆盖仅为显式标签访问/写、占用写与已检查候选边，不是完整内存访问。采样与截断必须报告；`dense_label_pages_512` 不等于物理页/DMA。`C_CPU_BUDGET` 是新增 CPU 重试实验，不能冒称原始 GPU/批处理回退。
- 预算规则已实现，见 `BUDGET_POLICY.md`：`profile` 默认 `off`，显式 `diagnostic` 保留探测；`auto` 需匹配输入/二进制/运行器/环境/阈值且通过端到端收益判据的真实证据，否则有效预算为 0。`budget-bench` 提供关闭足迹收集的成对 CPU 计时；当前预算 2/8 均未通过，不能根据合成计时或同 CPU 重试启用优化。未来后端须计入失败搜索、调度、传输及所有其他开销。

本方向重点语义：

- 包围盒不交不必然意味着长线物理资源不共享，按规范资源 ID 核验。
- 固定 halo 不能证明覆盖全部可行绕行；允许扩大区域或完整搜索回退。
- 中间资源超额与最终非法需要区分，不预设所有共享都必须拒绝。
- 样例的资源串行化只是保守调度基线，不宣称复刻现有路由器并行语义。
