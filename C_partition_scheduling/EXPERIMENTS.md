# 方案 C 实验设计

## 工作假设

联合搜索工作量、驻留复用和共享资源依赖安排任务，能否提高利用率并降低完整布线时间？

对照层次保持分开：已有方案、成熟方法的直接迁移、当前场景的适配方案；同时区分软件算法改动与 FPGA 执行收益。可以让本方向单独成为论文主贡献，不要求拼齐其他所有方案。

## 已实现与计划变体

| 变体 | 含义 | 状态 |
|---|---|---|
| `reference` | 在两个抽象 worker 上调度带依赖、资源集合和容量约束的任务；输出抽象工作单位的排程。 | 可运行 CPU 样例 |
| `existing_partition` | 现有分区/DAG 调度 | 待实现/接入 |
| `fixed_tiles` | 固定图分区 | 待实现/接入 |
| `workload_adaptive` | 按工作量自适应划分 | 待实现/接入 |
| `residency_aware` | 工作量 + 图页驻留复用 | 待实现/接入 |
| `cpu_fpga` | CPU/FPGA 调度 | 待实现/接入 |
| `cpu_gpu_fpga` | 三类设备调度；设备齐备后研究 | 待实现/接入 |

`existing_partition` 仍标为计划：目前只把原始分区树/DAG 在单 worker 下接入诊断并在合成图验证，未完成真实多 worker 性能基线。诊断入口独立于 `smoke --variant`，不会将该变体静默映射到 toy。

## 已执行的适配器验证

2026-10-22，`trace-smoke` 共 33 个设置/重复运行，每个与相同配置的 CPU 兼容对照比较 `.result` 字节。覆盖独立链、跨分区共享候选标签、同 net 共享路径、最终不同 net 超额、不可达连接。合成成功案例与对照一致；非法/不可达案例被独立路径/容量检查检出。详见 [实验记录](results/EXPERIMENT_20261022.md)。

预算 2 在两个 8 连接成功图上均触发 8 次退出，CPU 无预算重试均恢复；总队列 pop 从 64 增到 88，说明低预算探测具有额外工作量。本轮没有异构卸载，不能将它解释为加速。预算 8 触发 2 次退出，总 pop 为 82。预算沿用原始 `target` 先检查、`pops > budget` 时退出的语义，也不约束递归 lookahead 的工作量。

对 DFMAcc 第 4 节的可实现迁移：用实际 pop、足迹规模和历史耗时替代 polygon count/density，评估可变任务粒度；容量约束与密度补偿仍可作为方法基础。其几何独立性与边界分配不能直接移植到路由共享节点。当前先建立标签读写/占用/最终路径分层审计，再考虑自适应分区，尚未实现或宣称该迁移有效。

## 消融变量

预算保留条件已落地为 `src/budget_policy.py`，详见 [预算策略](BUDGET_POLICY.md)。`profile` 默认关闭；完整收益未证明时仅保留显式诊断。新 `budget-bench` 使用同一二进制、无足迹集合收集的成对 CPU 测量，记录丢弃搜索及完整进程开销；本轮 20 对正式测量未通过准入，见 [运行记录](results/BUDGET_POLICY_20261022.md)。不能用原先的 trace 对照进程耗时计算预算加速比。

- 任务划分策略
- 复用感知开/关
- 设备分配与预算阈值
- 工作集容量和跨区比例

先选能够回答主假设的最小对照，不强制穷举组合。交叉实验应检查相互作用，例如压缩与驻留、驻留与调度、内存后端与数据布局。

## 指标

| 指标 | 单位 |
|---|---|
| `pe_idle_ratio` | ratio |
| `transfer_bytes` | byte |
| `tail_task_ms` | ms |
| `fallback_count` | count |
| `reroute_iterations` | count |
| `routing_ms` | ms |

计时分别记录准备/构图、首次加载、状态初始化、内核、结果回溯、提交/同步、回退和完整流程。首次运行与驻留复用运行分别报告。硬件有效频率以实现报告/实际运行配置为准；CPU toy 的逻辑次数不换算成硬件周期或速度。

## 阶段验证

1. 接通真实软件基线，固定输入、工具/代码版本、环境变量与约束。
2. 接入真实数据接口，先验证与源工具的资源和结果语义一致。
3. 实现直接迁移的软件原型，复现和分析无收益案例。
4. 实现本方向的场景适配机制，与相同算法目标的基线比较。
5. 接入硬件并进行仿真/综合/实现或实卡验证，记录实际覆盖范围。
6. 回到完整布局/布线流程，检查质量、成功率、迭代变化和端到端收益。

这些是可复用的推进顺序，并非审批流程。根据已有授权与具体研究进展可以调整。

## 必须保持的语义

- 包围盒不交不必然意味着长线物理资源不共享，按规范资源 ID 核验。
- 固定 halo 不能证明覆盖全部可行绕行；允许扩大区域或完整搜索回退。
- 中间资源超额与最终非法需要区分，不预设所有共享都必须拒绝。
- 样例的资源串行化只是保守调度基线，不宣称复刻现有路由器并行语义。

## 可重复性与结果边界

真实结果保存数据哈希、代码版本、完整命令、设备/驱动/平台包、随机种子、重复次数和计时范围。`configs/experiment.json` 中尚为空的阈值和版本必须按真实实验填写，不能把 null 当作零。

相同输入与约束下比较，并报告失败、预算耗尽、回退及完整流程结果。若主张时序质量，需加入布后时序或经过验证的时序模型；线长不能代替时序。当前合成样例结果不能纳入正式论文性能表。
