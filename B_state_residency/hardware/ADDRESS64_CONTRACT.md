# 小页端点64位后备地址包装层

`hardware/variants/address64/memory_scratch_endpoint_address64.sv`包装静态codec小页端点，原生命令/响应和AXI数据/ID/握手保持不变，AWADDR/ARADDR扩为64位。输出地址为锁定的基址加原端点的32位相对地址。可与独立记录响应直通候选组合；默认RTL与现有全量回放不变。

本层只补设备缓冲区基址表达能力，不负责分配缓冲区、XRT/DMA控制、平台连接或图搜索。配置来源可由后续平台控制层提供，目前仍是原生valid/ready接口。

## 配置和生命周期

| 信号 | 含义 |
|---|---|
| cfg_base_valid/ready | 基址配置接受握手 |
| cfg_base_address[63:0] | 后备缓冲区基址 |
| cfg_rsp_valid/ready | 配置响应；背压时保持稳定 |
| cfg_rsp_status[1:0] | 0成功，1未4KiB对齐，2容量/64位范围溢出 |
| configured | 已接受成功配置，直到冷复位保持1 |

每个冷复位生命周期只接受一次成功配置。错误配置不启用端点，响应消费后可重试；成功后ready永久为0，不能在已有状态或在途AXI事务期间更换基址。冷复位同时重置整个原端点，不是热迁移或在途恢复协议。

未configured时cmd_ready为0，原生cmd_valid被屏蔽；配置期间可以由发送者保持待发命令，成功配置后才可接受。配置成功握手更新configured后即可接收原生命令，不额外等待配置响应被消费；主机控制流程可等待成功响应后再提交命令。初始化清表仍可在后台进行。

当前页格式固定192字节，窗口尺寸为FRAMES×192。基址必须4KiB对齐，以保持原相对地址引擎的4KiB拆分边界。使用65位加法检查最后一个字节的地址；末字节恰为2^64−1合法，真正溢出拒绝。原生FRAMES/INDEX_BITS/HASH_BITS等参数约束保持不变。

本层信任已验证原端点的相对地址范围，不是独立安全隔离器；数值窗口检查也不证明外部缓冲区实际已分配或地址在具体板卡上有效。接入方仍须提供大小足够、地址有效且与目标AXI端口映射一致的缓冲区。

## 已运行验证

- 配置单元：错误对齐、64位溢出、高于4GiB的基址、最后字节恰好落在64位上限、响应背压、配置锁定与冷复位。
- 高基址32槽集成：1778检查、288传输、8checkpoint、4次fence tag回绕；8类阻塞累计800周期。保留全部原页字节/AXI协议/租约/排空检查，并验证配置前无命令接受或AXI发送。
- 基址0x00000012fffff000集成：11次AW、88次AR跨越低32位边界，额外核对完整64位地址进位。参考内存模型用归一化偏移寻址，但独立检查实际64位地址，不能用截断掩盖高位错误。
- `audit_address64_endpoint.py`核对原端点源与冻结组合先导一致、包装层和检查器可重建、实际编译集合与日志哈希。

证据位于address64_endpoint_v3_20261024和address64_carry_20261024。v1混合声明、v2检查器隐式网络编译失败记录保留，均未启动端点功能仿真。

默认容量综合已通过：163840帧/hash18/epoch6，12512LUT/11183FF/303BRAM/3DSP，相对未包装组合版+78LUT/+68FF。高基址19查询实际值先导也通过，75194命令/5183传输，含时间收据和总周期与未包装先导完全一致；写/读地址进位分别覆盖2632/1884次。配置延迟与既有冷启动清表有重叠，不能由此声称配置在任意负载中零成本。独立物理已完成并审计：12480LUT/11182FF/303BRAM/3DSP，当前10ns内部WNS1.493/WHS0.041ns、失败端点0。但693输入/938输出缺延迟预算，地址加法外部路径和平台时序仍未闭合；完整38查询包装层回放、XRT与实卡结论仍缺失，旧组合版结果不能直接转用。后续仍需明确平台控制/缓冲区接口。
