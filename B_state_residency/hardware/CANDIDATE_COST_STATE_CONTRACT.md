# Candidate query and cost-state linkage

`candidate_cost_state_v1/candidate_cost_state_engine.sv` connects the actual candidate engine/pager query state to `cost_state_store`. The cloned `candidate_query_core.sv` only adds an output for the existing operation_pending net; its complete body is checked against the prior tested candidate_engine. Existing frozen candidate baselines remain unchanged.

OPEN requires all graph/design/owner/table/cost configurations to complete, matching accepted node counts, cost readiness, a full published version and matching low four-bit price identity. The wrapper retains the full version for the query and requires matching full versions on CP/CLOSE and each expansion descriptor. An eligible control/expansion with an invalid full identity stops admission without accepting that request; stale OPEN/expansion with the same low tag and mismatched node/design configuration have actual boundary tests; CP/CLOSE identity and other fault paths still need coverage. Configuration stores cannot authenticate imported file contents: the external design_id is checked against cost configuration, while original graph/design/owner interfaces carry node counts rather than design IDs. Same-size new designs still require coordinated reset and complete import.

Cost host commands have priority while editing so a queued OPEN cannot prevent PUBLISH. OPEN remains blocked until editing and its response/bus work finish. During an active query the cost store rejects host edits; this gate is driven by the actual pager's p_active/query/price outputs, rather than a testbench activity input.

Internal cost requests can be accepted during an owned candidate operation. They use its full query version and the store checks query2/price4/version32. Acceptance acquires cost_lease, which extends the decision lock through cost reply retirement and physical drain even if the candidate final response retires earlier. During that lease, new expansions and host label/control/design/owner work are blocked. External candidate output READY/VALID is not withdrawn to hide a pending cost request. A future internal cost consumer must apply its own output backpressure until calculations/commits are ready.

The functional test holds each candidate decision output while issuing actual AXI reads for child history, price[child ordinal %256], and its real net's parameter record. This is an interface/lifetime test, not occupancy-based price selection or a produced cost packet. It checks the original candidate decisions/Config14 unchanged and every cost read against the imported CPU image. One additional read at cookie10 is accepted before candidate final retirement, then held after the core operation retires to prove the extended lease. Queued OPEN versus PUBLISH is tested after closing the query.

The scripted query price tags3/5 are lifecycle identities; empty edit publications advance the full version from3 to5 and later6 while preserving the imported initial factor0.5 table. They are not claims about routing iteration3/5 prices. Additional joined update tests now SET history[0]=2.0 and price[0]=1.5, publish full version4, and read both through two actual pager query lifetimes. These scripted raw values test publication/persistence, not the original congestion-update formula. All cost beats and complete backing bytes are independently checked.

Additional evidence is results/candidate_cost_updates_20261025/source_bound_audit.json (eight selected cases: update, stale OPEN/expand, node/design mismatch, actual R/B errors, AR abort) and results/candidate_cost_default_20261025/source_bound_audit.json (default163840-frame/18-bit directory). Each fault case starts from a fresh design import; there is no in-session joined recovery proof.

Still required: remaining identity/protocol and in-session fault/reload boundaries; wrapper joint synthesis; actual internal history/price/net requests and occupancy-based price selection, connection parameters, post-prev geometry, exact cost packet production, acknowledged label commits, Frontier/recursive control, full routing and platform/board validation. Standalone synthesis resource totals must not be added and called the measured joined design.
