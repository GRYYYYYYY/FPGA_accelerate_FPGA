# 稀疏写回与回填控制契约

本变体继承 sparse_writeback 的驻留有效位图快照、仅有效 EXPORT 和八条规范 codec 输入。新增 REFILL 仅为有效记录发 BEAT，并以一次受信任 RF_MASK 完成无效偏移的表示。公开原生端点端口、192 字节页、AXI 地址/突发/字节量不变；默认 RTL 与原消融均保留。

## 原生闭合路径

1. REFILL 经原有 owner、发布状态、绑定、pristine 和事务预算检查取得租约。
2. codec 仍消费三个完整 512 位 AXI beat，验证页格式，按顺序输出八个偏移。上层必须消费全部八条输出，包括无效记录；偏移不符或无效记录非零均 fail-closed。
3. 有效记录（包括值为零的有效记录）依原描述符逐条 BEAT 并等待成功响应；无效记录不向队列发 BEAT，计入本地解码位图。
4. 全部八条解码输出及最后一个有效 BEAT 确认后，适配器发送内部 RF_MASK=14：payload低8位为有效位图，高位为零，原描述符/方向/事务保持一致。
5. 控制器验证 RF 描述符、未 sealed、payload规范且 `transferred == bitmap`，然后 sealed 并将八个偏移标为已表示。有效记录少确认、额外确认或位图不匹配不能通过；重复 seal 拒绝。
6. 原生端点仍等待内存成功，验证 cookie、frame和发布状态，之后才发送 COMPLETE，收到页确认后才 RETIRE，全部租约退休后才回复主机。新 seal 不是内存完成或发布证明。

RF_MASK 为受信任适配器控制，与现有内部 COMPLETE/RETIRE 一样有调用前提。单独控制器无法辨别调用者是否消费过整个 AXI 页；例如未加载记录时 bitmap=0 是合法的受信任空页表示。安全性来自闭合原生适配器在消费八条解码输出后才可发送它，而不是声称控制器能验证外部字节流。公开原生 ingress 始终拒绝 opcode14；原始队列保留12/13本地控制，14才转发至此变体控制器。

## 状态与失效

每次新 REFILL 清除该槽 rf_sealed，所有有效 BEAT 必须 present=1。直接控制器调用中不再允许无效 BEAT；完成之前 READ/WRITE 仍被 RF 阶段阻止。BIND 清除存储 present位；回收不会使旧数据、位图或 sealed 越过新描述符暴露。generation、事务、query/price、fence、同网占用语义均不放宽。

若内存/页/描述符错误发生，即使已提交部分标签或 seal，也不得 COMPLETE/RETIRE；保持 page/memory 租约与 fail-closed 隔离。CHECKPOINT、完整 fence 和目录 epoch 回绕仍须原闭合排空协议。

## 验证范围

全部256位图、有效零值、逐字节WB/RF、八偏移解码/codec完备性、精确有效确认集合、公开14拒绝、33项控制器边界、九类故障、32槽800阻塞/8CHECKPOINT以及65536次合法回收均有独立检查。新的先导计数器为unsigned64，FINISH状态7按明确边界验证后有界重试，响应等待亦有超时。测试台固定4周期响应检查及周期性背压仍计入时间。

位图与零记录省略是成熟的稀疏处理方法；本实验研究其与当前页租约、提交顺序、失效和回收协议的适配，不据此宣称通用方法新颖。全部传输字节仍发送，未实现压缩或DMA加速。先导不是完整38查询、完整路由器、平台时序闭合或板上加速证明。
