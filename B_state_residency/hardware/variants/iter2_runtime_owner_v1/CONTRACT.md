# Runtime owner delta production before real G2 publication/warm recovery

Derived from iter2_g2_warm_v1. The candidate owner file starts as the original G1 image, not the previous experiment's prepared G2 image. Actual q180327 commit and historical-path ripup produce six native owner writes. incremental_owner_snapshot captures their four distinct physical 64-byte lines from actual AW handshakes, including two lines whose final contents revert to the baseline.

Under the actual PC lease, the native producer copies/readback-verifies those four lines from the current working DDR into the G1 baseline clone. owner_snapshot_checkpoint_adapter supplies real receipt-based jp_manifest_ready and protects checkpoint lease release until the producer reply retires. Then unchanged native authority/config/coordinator jointly publish G2/CP18, and the existing q180328 second-owner-B fault, real G2 two-key repair, 822-label/path/query restore and attempt4 retry execute.

The new copy master is modeled as a second coherent DDR port using the same actual work/candidate files, with no answers read from DUT arrays or injected callback values. A simulation-only file-agent option enables writes to the second file window; default behavior is unchanged. This is not an implemented board interconnect. Independent audit covers the original eight AXI logs plus the four source reads, four destination writes and four verification reads on this ninth AXI master, exact source/candidate bytes, full 146284032B candidate/work images, four-line source footprint, actual producer and publication ordering, and complete subsequent warm recovery.

Remaining premises: an external exact G1 baseline clone and trusted epoch setup; observed single owner writer; MAX_DIRTY=64 fail-closed capacity; fixed G1/G2 window and namespace coupling; externally supplied historical path metadata and CPU conservative 822-label read closure. Labels still are not exported by a runtime directory/snapshot producer. No arbitrary concurrent DDR writers, dynamic baseline rotation/rearm after source write error, persistent authentication/floor, general unknown-page initialization, synthesis/timing or board performance proof.
