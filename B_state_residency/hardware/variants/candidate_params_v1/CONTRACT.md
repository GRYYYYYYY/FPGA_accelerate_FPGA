# Candidate expansion State parameter ownership

This wrapper derives from frozen candidate_postprev_engine; core, memory services, post-prev and Frontier modules are unchanged. derive_top.py reproduces the wrapper transform for review without altering the old source.

Caller provides the actual global connection index with each accepted expand. The wrapper snapshots cookie/net/sink/cross, query2/price4/full version32/design64 and the separately configured immutable State profile revision. Exactly one64B table request belongs to that expansion. Immutable graph/owner/cost prefetch can overlap; post-prev write initiation, candidate output and final result (including empty expansion) wait for matching State metadata. Metadata is held across all candidate replies, and full active identity remains checked until operation retirement.

Reader pending/busy participates in state_lease, configuration and host edit/control guards. All configurations must have completed before query OPEN. Configured nodes/net count/design must match the existing graph/cost/design configuration. Reader failures or mismatched response identity stop wrapper admission. Joined fault drain/reset/reload is not yet verified; standalone reader tests cannot establish the joined recovery contract.

The table is initial serial non-timing State, not a live routing trace. This profile has landmark inactive and no crossSLR connections. Geometry-specific stress inherited from postprev explicitly forces hasLaguna and patches four SLL beginY halfwords in a separate graph image. Allowed candidates in this joined gate have zero occupancy/refs/price index. No combined nonzero-owner claim.

This stage exposes imported parameters and retains actual CLEAR/prev ACK/parent upstream/fresh effectiveY/center computation. It does not yet form or calculate the complete23-word cost, commit lb/upstream/visited, perform OFFER/recursive lookahead, run full routing, or establish board acceleration.
