# Ordered cost-label commit

The new wrapper derives from frozen candidate_cost23_engine. Only a fifth native IO client is added to its core. After the actual cost result, cost_label_commit snapshots cookie/parent/child/route-sequence, partial/total and active query2/price4/full version32/design64. It writes lb(field0)=newTotal, then upstream(field1)=newPartial, then visited(field3)=the route sequence. Each write waits for a successful native ACK before exposing the next. Every ACK must be present, preserve prev=parent and contain the just-written field; later ACKs also verify earlier cost fields. The complete160bit payload is checked independently in the joined regression.

Candidate output is held until all three ACKs; rsp_acked=111 then. Route sequence is out_config word0, not the child ordinal out_sequence. Commit response and metadata remain stable under candidate backpressure. commit_busy joins the existing mutation/config/host fence. Cost, post-prev, State and prefetch replies retire with the same candidate. Query OPEN still invalidates native connection labels; design owner/history/price storage is independent and stays unchanged.

The new CPU stream uses the real arithmetic plus the verbatim three-assignment prefix of original push. Manual access-state-machine replay and original candidate control run from identical full SparseLabels snapshots and compare all five live label words after every parent. Their changed later decisions are used for the RTL comparison. Queue OFFER and recursive lookahead are not executed in this label-only stage. This is a scripted stateful prefix regression, not full route equivalence. The repeated sequence100 in the second scripted query deliberately permits cross-expansion visited reuse; it is not a natural per-connection search trace.

The complete regression also reads all nonzero final native label records after checkpoint and compares all five fields with the CPU state. Single-slot pressure forces the same data through eviction/reload. Physical AXI label journals and all backing bytes are checked separately. Existing explicit four-node SLL beginY/hasLaguna stress remains; real profile crossSLR0/landmark inactive and the separate earlier nonzero-owner gate do not establish combined coverage.

Commit status0 is successful; status1 rejects a bad native ACK, status2 indicates abort/drift/timeout/unexpected reply. rsp_acked counts the validated ACK prefix, not all physically completed writes. Errors stop admission until reset. An already exposed SEND remains valid until accepted, and a pending reply remains ready for drain even if the logical error response has retired; busy covers that drain. No new stage is started after fault. Previously validated writes are not rolled back, and a failing write may already have changed memory. Already offered replies stay stable under a late fault; consumers must also check fault=0.

Standalone mocked-native tests do not prove drain/reload in the joined wrapper: its global abort can also stop the backend. Coordinated quiesce/reset/reload is still required and unverified for this composition. Never reset only the commit block while old native traffic exists, and never clear design-level ownership/history with connection labels.

No actual cost OFFER, immediate recursive scheduler, full search/traceback/owner-reference commit, joint/default-directory synthesis, platform integration, physical timing or board speedup is established here.
