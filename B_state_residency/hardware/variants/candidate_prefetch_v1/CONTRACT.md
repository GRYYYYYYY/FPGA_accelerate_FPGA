# Internal congestion and net-parameter prefetch

`candidate_prefetch_engine` extends the separate center-lifetime variant with an internal read-only producer. A stable allowed candidate (action1/2) automatically triggers a new owner lookup followed by history(child), price(selected occupancy) and net(actual expansion net) reads. SKIP (action0) does not perform these reads. The candidate output remains backpressured until all fields arrive, and its operation lock stays held. A one-cycle raw-output qualification avoids interpreting an old action while candidate data updates on the same edge.

The owner backend is shared with the access bridge through a transaction owner bit latched at request acceptance. Access has priority; prefetch always uses raw owner op0. Responses are routed to exactly the requester that owns the transaction. No host port is repurposed to bypass the operation lock. The cost-state backend uses another latched owner bit, with prefetch priority; the external host/test port cannot enter while prefetch is active. Accepted backend responses continue through the owning path.

The output fields are same-net reference count, distinct-net occupancy, selected price index, raw history, raw present price and raw128 net parameters (centerX/centerY/fanout/doubleHPWL). Selection follows the original getNodeCost: occupancy minus one when same-net references are nonzero, otherwise occupancy. References7 or65535 still subtract exactly one because occupancy counts nets, not branches. Nonzero references with occupancy0 and any selected index outside0..255 fail without issuing a cost read. The service reports status1 for an owner response/index error, status2 for a cost reply error, status3 for other failure detected at an owner reply; persistent fault is authoritative even when a previously exposed status remains0.

Cookie/node/net/query2/price4/full version32/design64 are captured once and checked through the producer. Full cost response identity includes op/index/host as well. Ownership remains active through result backpressure. Design history and owner state are never cleared at a query boundary. This stage makes no label or ownership mutations.

Abort, drift, malformed response, or bounded timeout persistently stops new admission. Captured downstream requests remain offered in OS/CS; replies in OW/CW are drained to an error result. A downstream service that has itself stopped may never accept an unaccepted logical request; coordinated reset/reload is then required. This is not a proof of joined AXI fault recovery or rollback. A completed exposed result stays stable on a late fault, and the consumer must check unified fault.

The present cost-state image is original initial history1.0 and the initial price factor0.5, with scripted version tags3/5; these are not actual routing iteration3/5 prices. Real input-source and raw AXI checks verify what was read. Standalone mock data separately exercises all selector boundaries and identity failure paths; it is not substituted for real-store integration.

The center service is retained with its explicit external test fixture. This prefetch is the immutable design-input part of cost packet production; it does not write prev, read post-prev effectiveY or parent upstream, produce connection weights/geometry or all23 cost words, commit cost labels, manage Frontier recursion, trace back, or update owner references. Reads may safely be prepared before those later ordered steps because the continuous operation fence prevents design mutations. EARLY's required Frontier CLEAR before prev remains outstanding. Default directory, new mapped area, new joined fault recovery and board evaluation are separate gates.
