# Candidate and center service ownership

`candidate_center_engine` extends a separate copy of `candidate_cost_state_engine`; the previous source and all its frozen baseline results remain unchanged. It reuses the same `candidate_query_core`, cost state store, graph/pager/owner services and the actual generated center-distance RTL.

A center request is admitted only while a candidate operation is pending, a query is owned and active, and the unified fence has no fault. Requests carry design_id64, query2, price4 and full version32. Design identity must match the configured unified design; query/price/version mismatches are returned by the center call service as admission status2, without starting arithmetic. The design identity is retained through reply retirement and checked for drift; center service checks active query/full version during successful calls.

The shared mutation fence is `state_lease = cost_lease || cc_busy`. It blocks query admission and CLOSE/checkpoint controls, another expansion, host label/design/owner mutation, host cost edits and all five graph/design/table/owner/cost configuration channels until arithmetic reply retires. Internal cost reads may overlap a center call while the original candidate operation is still pending; after core retirement only already accepted requests continue. The core exposes operation_pending unchanged. A computation may finish after the core result retires; the center reply remains owned and backpressured independently.

Center fault or design identity violation propagates to unified fault and persistent fence stop. Existing core and cost AXI services see the stopped fence on subsequent clocks and retain their existing physical-drain semantics. A shared synchronous reset resets the arithmetic core, collector, and existing services. Joined fault/drain/reload recovery has not yet been tested for this new composition and must not be inferred from standalone recovery tests.

The current external cc_req_words port is a temporary producer boundary. The joined regression uses the explicit fixture `(childX=3, effectiveY=-4, centerX=0, centerY=0)` with expected binary32 distance7; it proves actual computation ownership against real candidate operations, not post-prev geometry, net-center lookup, or a cost23-word producer. Existing history/price/net requests remain TB-issued. No internal cost label commit, Frontier recursion, full route, or board acceleration is claimed.

Tests deliberately hold the arithmetic reply after each candidate final result (except cookie10, reserved for the old cost-AXI retirement test), offer all configuration and host interfaces during this interval, and require no READY or mutation. Decisions and whole final design/owner/cost images are checked against the old CPU-derived expected files. Full and one-slot pressure configurations are distinct runs. Default directory, new joined identity/fault cases, platform delays, and new mapped resource totals remain separate work.
