# Candidate pipeline integration

`candidate_pipeline_v1/candidate_engine.sv` joins actual CSR graph reads, persistent design state, children HLS filtering/cache publication, metadata production, access HLS decisions, label paging, coordinate service, and AXI owner reads. Graph, design and pager IO each have a serial request arbiter that captures payload and client identity before forwarding. Actual leaf services retain their response until accepted; a one-cycle unretained combinational reply is outside this arbiter contract.

An expansion descriptor contains parent/sink/net, cookie, sequence, bounding box, prune, has-Laguna and option flags. `expand_flags` accepts BB/NORTH/SOUTH/HOT (`0x11c`); prune is separate. Parent/child/sink metadata and the persistent child design record produce Config14. Host cannot supply dead/type/Laguna/pinbounce values. Accepted graph/design/owner node counts must agree. Equal node count is not DesignID verification: importing another design requires coordinated reset and complete design/owner import.

`operation_pending` spans expansion acceptance through final response retirement. It gates label controls/IO, host design updates and host owner requests throughout child extraction, metadata, access and output stalls. Owner queries use the same actual store initialized from the CPU loader's state. This stage has no owner mutation or cost/Frontier update. The backing image's pool capacity64 suffices only for the initial overflow-free read-only workload; it does not bound full routing (the real workload previously reached53734 overflow entries).

Each externally retired child has a decision, including SKIP, with Config14 and original child attributes. EARLY terminates further metadata/access evaluations but drains the remaining immutable cached child stream. Final `result_count` is evaluated-prefix length; `result_expanded_count` is the full filtered children count; raw count/mask/cache-hit come from actual expansion. This extra replay drain is not an optimized early-exit implementation.

Abort, context drift, timeout and service faults cause a coordinated stop. Modules may expose error before raw bus drain completes, so reset/recovery requires the existing drain/reload protocols; failed writes are not rolled back. The outer controller now tracks accepted metadata/access requests and the expansion completion separately: expansion completion alone cannot expose the final response while an accepted logical service reply is outstanding. Unowned replies stop admission. Controlled reply fault tests cover identity, context drift, timeout/final ties and stable exposed responses. Actual AXI fault coverage is tracked separately in the experiment report. Current tests do not establish reset timing for a board/interconnect.

The CPU fixture preserves original getChildren and the original exploreAndExpand decision body, replacing only evaluateCostAndPush by recording. It compares allowed child/lookahead/early/pruned behavior with access_machine for all evaluated children. Query label values and occasional target flags are scripted test state; they are not a full live search. Dynamic labels are not updated by a cost/push stage here. Real initial owner records are exported independently and match the prior real loader-event prefix for all9089009 nodes and180326 occupied nodes.

Remaining research work includes integrated fault/identity tests, cost and geometry after real prev/visited writes, Frontier, recursion/backtrace/commit, full routing, platform and board measurements. Neither simulation cycles nor standalone synthesis resources establish acceleration.
