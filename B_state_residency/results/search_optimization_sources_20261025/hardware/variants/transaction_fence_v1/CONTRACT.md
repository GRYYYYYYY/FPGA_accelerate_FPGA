# 事务归属与恢复围栏

transaction_fence 缓存已接受的主机请求和192位route命令，分别跟踪正常主事务、父事务续接、route和恢复回调归属。默认16入口、2432位request容器、256位reply容器；typed field宽度由transaction_fence_join_v1/layout.json规定。6配置/控制/design/label/owner/cost-center/expand/frontier/cost与2可信管理入口共16类；管理入口为coordinator checkpoint配置和常驻设备描述符装载。管理可在work_permit为假但系统无故障且已排空时初始化；不能越过route/recovery所有权。正常主事务串行，恢复config回调可按端口并行。

关闭新准入不撤销已暴露的后端VALID。普通主机输入先被缓存，后端接受后保持回复归属直到原调用方握手；全局backend_drained及backend_idle再决定是否让出所有权。route同样先缓存，后端VALID和payload不依赖之后前端输入变化，回复退休前不交给恢复。route错误退休可进入BLOCKED，只有恢复请求可接管，不能直接重试。

扩展父事务（默认lane11）可能需要cost-center续接lane10或nonhost cost续接lane13才能退休。它们只可在该父事务仍持有后端时进入，恢复请求先关闭新父事务，允许其必要续接排空。host cost（host flag=1）是普通独占主事务；nonhost cost不能单独启动。父回复一旦对前端VALID就不因新续接撤回；前端可先退休父回复，模块会继续持有后端父回复，直到已接受续接全部退休后才ACK后端，因此原operation_pending上下文不会提前释放。父前端已退休后不接受新续接。若调用方不完成既有请求/回复，恢复会等待，不把背压伪装成取消成功。

恢复请求在所有正常已接受事务（含续接）、route回复、物理与逻辑后端都静默后才送coordinator。recovery_owned期间全部16主机及route入口关闭，回调只允许mask0x037f的六配置、control、label、owner；逐端口记录pending请求直到相应回调消费回复。回复直接回原调用者，不由实时mode猜测。恢复完成响应还需回调pending/VALID都清空且后端排空，持有期间不放行；失败进入BLOCKED。非法回调lane锁fault，不当作正常请求转发。

normal_retired只表示fence已接受的正常事务账本为空，不能用它代替backend_idle/物理排空。原engine的busy混合了在途状态和故障锁存，后者即使没有任何调用也可为真。隔离backend派生源新增retired_idle出口：prefetch/postprev/cost23/center/frontier及其HLS子调用必须在IDLE、无未退休回复、无owned调用，HLS还需ap_idle；仅忽略“idle时的sticky fault”对busy的贡献，真实RUN/REPLY及子调用不能变成idle。原busy/fault/算法状态机不修改。build_backend.py从冻结基线重建13个导出变体，原共享基线文件不改；97原RTL/dat逐SHA保持。

真实接入在七类现有单挂起AXI接口上使用axi_drain_watch，计数及所有VALID都静默才drained。观察器不支持任意多ID/乱序/同时重叠AR，不能推广为通用AXI firewall。cold_rst仅清本fabric账本，不能连target_reset；target reset只能在所有权与排空条件已满足时由coordinator发出。watchers和原服务可接target_reset。实体端口连线与CPU snapshot生产仍在验证TB中，完整可综合系统top尚待抽取；本模块与宽度绑定OOC不是完整系统资源/时序证明。

围栏只处理归属、准入和排空，不自动扩展checkpoint覆盖范围。owner journal当前仍只覆盖route controller修改；legacy owner/design/cost写入尚无完整快照/日志恢复保证，不能将这次route故障恢复结果外推给任意入口修改。初始可信checkpoint/描述符安装、CPU authority与328条标签snapshot生产依然外部。完整warm/frontier/path/design-created、unknown-page、实际价格变更/回绕、容量预留、耐掉电和板卡尚未完成。真实所有权测试的五类故障发生于route阶段，恢复期失败及完整正常search/共享ripup在新fabric下仍待回归。
