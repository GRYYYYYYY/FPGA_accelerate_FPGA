# 2026-10-22：状态原语首次计时与消融

本轮已把状态分配、显式 reset、标签访问、同网准备、rip-up、commit 和主机增量打包拆开。逐节点 epoch 在分散访问上改善了原始整页初始化，但尚未超过串行 visited 标记策略；同网哈希引用索引未显示整体收益。以下都是 CPU 合成状态实验，不是完整布线、GPU 或 FPGA 加速结果。

- [ASan/UBSan 与语义检查](state_microbench_20261022T145247.685804Z.json)：status=passed，性能样本为空。
- [负载配置](../configs/state_microbench.json)、[C++ 实现](../src/state_bench.cpp)、[源码提取器](../adapters/extract_state.py)、[测量脚本](../scripts/benchmark.py)。

执行 `python3 scripts/run.py benchmark` 可生成新的独立结果；`python3 scripts/run.py benchmark --self-test-only --sanitize` 只做检查。另有五个 Python 测试，检查真实输入/未知变体/非法参数拒绝、差分异常检出和禁止覆盖结果。

环境为 Intel Xeon Gold 6530，Linux x86_64，进程绑定 CPU 0，g++ 使用 C++17、-O3、-fno-fast-math，不启用 -march=native。运行顺序按固定种子打乱。环境并非独占，负载均值开始/结束约为 5.50/8.66；所有原始样本及 min/max 均保留，不能把小差异当成确定收益。

共 262144 个资源、4 个 net。短访问为 128 个查询，每查询 256 个 ID、重复访问四轮；长访问为 32 个查询，每查询 16384 个连续 ID、四轮访问。常规每 net 4 分支，高扇出每 net 128 分支。路径具有共享干线、分支及排除占用的两个端点，但没有真实图。每种设置使用三个种子、各重复三次。每样本在同一分配状态上回放两次，标签每个查询都失效；复用不是跨查询沿用距离。

## 主要结果

下表是页大小 512 时，第二次回放的**状态阶段合计中位数，单位 ms**，每格九个样本。稠密两个变体不使用页。合计不包括构造、图遍历、路径生成、验证和设备传输。

| 合成负载 | 全量清零 | 串行 visited 标记 | 原始分页 | 分页 + 逐节点 epoch | 逐节点 epoch + 同网哈希索引 |
|---|---:|---:|---:|---:|---:|
| 局部短访问 | 40.062 | 0.491 | 0.734 | 0.703 | 0.839 |
| 分散短访问 | 40.139 | 0.683 | 12.303 | 1.100 | 1.247 |
| 高扇出 | 41.096 | 1.524 | 1.851 | 1.764 | 1.995 |
| 局部长访问 | 15.145 | 5.207 | 8.611 | 8.799 | 8.670 |

原始串行搜索本来就使用 visited 标记，不能把全量清零视为唯一现有基线。这里把相同的共享集准备加在各状态实现上用于控制变量；原始普通串行 CPU 搜索不调用 gatherShareSet，该函数属于 GPU flood 的主机准备路径。因此“串行标记”这一列也不是原始路由器全流程时间。

两轮之间执行不计时的独立占用重建检查，会影响缓存内容；第二轮表示复用已分配存储，不保证缓存全热。

分散短访问的原始分页标签阶段约 12.104 ms，逐节点 epoch 为 0.942 ms；显式 reset 都约 0.003 ms。热点在首次触页处理，不能仅凭 reset 为 O(1) 就认为初始化已消除。相应状态合计范围：原始分页 11.811～24.315 ms，逐节点 epoch 1.049～1.314 ms，串行标记 0.607～0.755 ms。长局部访问中，逐节点 epoch 相对原始分页没有稳定改善，不能外推所有工作集都受益。

同网哈希索引的局部短访问准备中位数从约 0.038 ms 降到 0.024 ms，但 commit 与 rip-up 两项中位数之和从约 0.055 ms 增到 0.181 ms，整体更慢。高扇出时准备阶段从约 1.083 ms 增到 1.237 ms，哈希迭代本身也未胜过扫描。当前结果支持保留负例，并在真实轨迹确认热点后再评估连续节点列表及增量索引。

## 页大小与首次分配

下表只展示分散短访问的复用状态合计中位数，单位 ms；其他页大小组合完整保存在 JSON 中。

| 每页节点数 | 原始分页 | 逐节点 epoch |
|---|---:|---:|
| 64 | 2.370 | 0.961 |
| 512 | 12.303 | 1.100 |
| 4096 | 32.474 | 1.309 |

原始 SparseLabels 无条件预分配 2048 页，原样保留于本次对照。512 节点/页时标签 vector 容量约 24.004 MiB，逐节点 epoch 增加到 28.004 MiB；两个稠密实现为 6 MiB。该输入规模下预分配池大于稠密数组，因此不能宣称分页节约总内存。这里未计 allocator 元数据、共享设计状态或 net 索引，也不是 RSS。

分散短访问的标签首次分配中位数约为：串行标记 2.115 ms，原始分页 9.089 ms，逐节点 epoch 10.786 ms。首次回放状态阶段分别约 0.698、13.034、1.181 ms。分配和回放分开报告，没有将第二轮时间冒充首次流程；共享状态初始化尚未纳入全流程计时。

独立插桩运行中，分散短访问、512 节点/页、种子 1 的两轮合计触发 51778 次首次触页，逻辑清零量 636248064 byte，首次触页处理累计约 21.657 ms。该时间包含探针扰动，是诊断依据，不能与未插桩运行直接计算速度比，也不是实测 DRAM 流量。

## 语义与适用范围

- 原样提取 NodeDyn、SparseLabels、owner-slot 增减/提升、rip-up/commit 和 gatherShareSet；各片段哈希、起始行与整个源文件 SHA256 在 manifest 中。
- 保留设计级 history，不随 connection reset 清除；资源占用按不同 net 计数，同网分支保留引用关系。提交后用路径重建的独立参考检查占用和引用。
- 检查有限 epoch 回绕、物理页槽复用与扩容、静止边界回收、独立上下文隔离、每次新搜索使旧距离失效，以及逐次共享集对照。上下文测试是串行交错，不证明并发原子性。
- 仅模拟串行 CPU 权威占用；HotExpand 缩为占用镜像。增量打包使用合成价格公式，无传输、GPU/FPGA 内核、真实拥塞收敛或布线质量验证。sync 字段只能表示主机打包耗时。
- 没有真实器件/输入适配器，原始包也不包含所需运行时与器件库；完整路由性能仍未测量。
