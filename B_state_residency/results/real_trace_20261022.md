# 真实访问轨迹与完整 CPU 路径占比（2026-10-22）

已接通 FPGA24 的真实已布局设计 `logicnets_jscl`，完成原始串行 CPU 布线、阶段计时、PC 采样和访问轨迹。**真实访问具有明显稀疏性，但当前串行路径的初始化开销很小，不能把合成分页微基准的收益直接解释为完整布线加速。** 本轮没有修改路由算法，也没有 GPU/FPGA 性能结果。

## 数据、运行时与来源纠正

- 输入为本机 `FPGA_Acc/projects/persistroute/third_party/fpga24/logicnets_jscl/` 中的 `.netlist` 和 `_unrouted.phys`，保留许可证引用。器件 `xcvu3p-ffvc1517-2-e`。真实设计共 37,082 个 net；导出的问题含 27,960 个待布信号 net、180,326 条间接连接和 9,089,009 个图节点。
- 输入、导出器和运行时的 SHA256 见 [provenance](../data/derived/logicnets_jscl_provenance.json)。冻结 RRT1 为 495,649,674 字节，SHA256 `d03de37af1a4a0b10f8bb29812b0048c4d2dd57ba6dadb70f61853225e39b6f4`。
- `rapidwright_runtime.zip.zip` 来自上级原始提交包 `9.EDA赛道_运行时间优先的GPU加速FPGA布线_复旦大学_林子涵.zip` 内部，**不是本次生成的文件**。其加密文件清单见 [runtime_inventory.json](../data/raw/runtime_inventory.json)。目前不知道密码；文件名和所在包不能证明具体制作人员。
- 改用官方 [RapidWright v2025.2.1-beta](https://github.com/Xilinx/RapidWright/releases/tag/v2025.2.1-beta) standalone Linux 运行时，核验官方 MD5，并在本目录加载匹配的 xcvu3p 器件数据。jar SHA256 `0c68053094351987a16920b05f155e3b7180f9080ff0a3316b979cbeaa6b7534`。没有绕过原 ZIP 密码。
- 更正此前 NEXT_STEPS 中“未找到真实输入/运行时”的说法：此前文件检索遗漏了被忽略的目录；后续用 `rg --files --hidden --no-ignore` 清点。原始包的 `rewrite/BUILD.md` 所述缺失不能推导为整台机器没有数据。

Java 适配器直接读取真实 Interchange，沿用原始导出器及 `--nonTimingDriven --fixBoundingBox`。为兼容官方 jar，仅在本地导出器副本中将两个 **RRT2 专用** `rwMaxThreads()` 调用替换为 48；实际使用 RRT1。C++ 本地副本仅为未启用 CUDA 的编译路径补上一个宏保护，其余算法不变。共享原始源码 SHA256 保持 `cbd6e0b810a46ca06b0058ee7f2318a1862f66c64178bf27f0d6b574e5bf6826`。

## 测量方法与正确性

[主实验 manifest](real_trace_20261022T165136Z/manifest.json) 保存完整命令、环境、输入/代码/二进制哈希、执行顺序、计时及验证结果。Xeon Gold 6530，绑定 CPU 0，串行运行；g++ C++17、`-O3 -fno-fast-math -fno-omit-frame-pointer -no-pie`。每次进程重新加载 RRT，文件缓存未清空；这不是跨进程状态驻留复用实验，也不是独占机器的固定频率测量。

三次原始运行、三次阶段计时/采样运行采用固定种子打乱顺序，另跑一次固定间隔访问轨迹和一次超大搜索补充轨迹。八次最终 `.result` 均为同一 SHA256：`428fa84ffa9e9839965c5000a32a4078f2fc7ea3f787a50cd4f7aff57447aa84`。收敛序列也相同：12 轮、570,286 次搜索、130,334,832 次入队，最终过用和未布通均为 0，usedNodes=722,477、totalLen=268,901。

独立结果检查读取冻结图和输出，对全部 180,326 条连接、3,092,250 条路径边检查端点、边存在性、环路和不同 net 的资源冲突，错误均为 0。同网分支共享资源允许存在。检查不在计时区间内。这是**导出图层面的合法性验证**，尚未回写物理设计并执行 Vivado route-status/DRC/时序验证；时间也不包括一次性 Java 导出、逻辑综合或布局。

## 实际阶段时间

原始 CPU 三次测量：

| 阶段 | 中位数 | 范围 |
|---|---:|---:|
| 读取 RRT、构造图与初始状态 | 1.891 s | 1.886–1.951 s |
| 布线，含 bbox 准备与拥塞迭代 | 23.220 s | 23.001–23.221 s |
| 写结果 | 0.585 s | 0.582–0.591 s |
| 程序内三阶段合计 | 25.697 s | 25.534–25.699 s |
| 外部进程墙钟，含退出回收 | 25.808 s | 25.658–25.808 s |

原始运行峰值 RSS 约 2.55 GiB。bbox 粗网格准备/求解约 4.57 s，已计入布线时间，占约 19.7%，没有从分母去掉。

以下为三次插桩运行的阶段中位数和各次比例的中位数；加载阶段使用该次加载+布线+写出总时间为分母，其余使用该次布线时间。逐连接 scope 计时会有调用开销，阶段间中位数不要求精确相加。

| 状态阶段 | 时间 | 占比及分母 |
|---|---:|---:|
| 标签首次分配/初始化 | 42.19 ms | 总时间 0.163% |
| 全部可变状态初始分配/初始化（包含上一项） | 243.72 ms | 总时间 0.936% |
| rip-up | 153.83 ms | 布线 0.660% |
| commit | 165.64 ms | 布线 0.713% |
| 路径回溯 | 162.37 ms | 布线 0.696% |
| target 设置 | 22.90 ms | 布线 0.099% |
| target 清理 | 15.67 ms | 布线 0.067% |
| 迭代边界拥塞/历史更新 | 182.39 ms | 布线 0.784% |

原始串行路径使用 visited 序号，**没有每个 connection 的全量标签清零**。初始化两行是包含关系，不能相加。`gatherShareSet` 是 GPU flood 的主机准备，本轮 CPU 路径未调用；设备同步/传输没有测量值。

插桩后的布线中位数为 23.314 s，相比原始中位数约高 0.40%；只有三次重复，不能据此精确分离计时器开销与运行噪声。完整访问记录运行耗时 31.345 s，尾部补充运行 29.592 s，均只用来取得轨迹，不参加原始性能统计。

## 标签访问与同网查询的 PC 采样

利用 SIGPROF/ITIMER_PROF 记录当前 PC 和最多八层栈，结合同一二进制的 DWARF 行号解码。请求间隔分别为 1/5/11 ms，实际得到 5,882/4,660/2,109 个样本（合计 12,651）；1 ms 请求受内核分辨率影响，实际约 4 ms。原始 PC、符号映射、归类规则和各次结果保存在 [sampling_analysis.json](real_trace_20261022T165136Z/sampling_analysis.json)、`symbols.json`、`profile_*.pcs` 和 [分析脚本](../scripts/analyze_real.py)。

| 排他采样分类 | 中位占比 | 三次范围 |
|---|---:|---:|
| 标签访问相关源码（TLD/visited/prev 等） | 3.43% | 3.27–3.60% |
| 标签数组预取源码 | 4.84% | 4.53–4.88% |
| 同网引用查询 | 6.87% | 5.83–7.43% |
| 历史价格读取/计算源码 | 1.90% | 1.82–1.97% |
| 邻接访问/生成 | 10.64% | 10.46–11.76% |
| 优先队列 | 9.42% | 9.38–9.91% |
| bbox 准备 | 19.08% | 18.82–19.16% |
| 其他扩展与代价计算 | 37.55% | 37.25–37.77% |
| 未解析/库代码 | 1.38% | 1.09–1.50% |

其余为路径管理、迭代更新和控制；完整分类见 JSON。阶段上下文优先分类，例如 bbox 内的队列操作仍计为 bbox；表内各项中位数不可要求相加恰好 100%。

**源码位置采样不是精确的访存延迟拆分。** 优化编译会重排指令、合并行号，预取源码处的样本不等于“预取可删除的成本”，程序位置也不能把缓存未命中停顿完全归到单个数据结构。重复范围不是置信区间。表中数据只用于定位下一步候选，不能据此直接预测加速比；阶段计时与 PC 分类也不能混加。

## 真实访问稀疏性和尾部覆盖

[主轨迹分析](real_trace_20261022T165136Z/trace_analysis.json) 验证全部 570,286 次搜索的顺序、connection 身份、拆线前路径与前次提交路径连续性、访问偏移、节点范围和迭代数量。共发生 **1,251,357,141 次 TLD 调用**；这是源码标签访问次数，不是 DRAM 事务数量。

固定每 512 次搜索抽取一次，共 1,113 条完整查询、2,399,968 次访问，0 截断。独立节点数中位数 274、p99=1,791、最大 4,925；每次搜索不复用上一次距离标签。全体 net 扇出中位数 1、p99=128、最大 303；按连接加权的扇出中位数为 85，两者口径不同。

全体搜索中有 19 次 pops≥16,384，最大 173,418，固定间隔样本没有抽到。补充运行按这些 attempt ID **全量记录所有 19 次**：13,751,567 次访问、0 截断，占全体标签调用约 1.10%。其独立节点数中位数 46,359、最大 310,972。补充运行的访问总数、收敛过程、最终结果与主实验一致，见 [尾部 manifest](real_trace_20261022T165136Z/tail/manifest.json) 和 [尾部分析](real_trace_20261022T165136Z/tail/trace_analysis.json)。两类采样不混合估算总体平均。

页密度定义为 `Σ每次查询独立节点数 / Σ(每次查询触达页数 × 每页节点数)`，节点沿用冻结图的真实 ID。清零槽位放大为其倒数：

| 每页节点数 | 固定间隔样本密度 | 整页槽位/实际独立节点 | 19 次尾部密度 | 尾部槽位放大 |
|---|---:|---:|---:|---:|
| 64 | 3.973% | 25.17× | 15.045% | 6.65× |
| 512 | 0.538% | 185.97× | 3.480% | 28.74× |
| 4096 | 0.0763% | 1,311.18× | 1.449% | 69.04× |

首次迭代与重布、高/低扇出分组均见 JSON。固定间隔抽样可能有任务顺序偏差，单设计和现有 ID 编号也限制推广。表中页大小是标签分页粒度，**不是操作系统页大小**；槽位放大是将串行真实访问映射到假设分页布局的逻辑计算，不是实测内存流量、CPU 时间或硬件加速倍数。实际分页的跨查询驻留和重复访问成本仍需集成后测量。

## 对方案 B 的影响

1. 串行初始化、target 清理和提交已经很便宜。仅优化这些阶段难以得到显著的整条 CPU 路径收益，不能继续只与全量清零对照。
2. 稀疏访问在真实器件 ID 上成立，支持继续研究多上下文标签的容量与触页代价；下一步应在真实并行/分页入口比较原始 SparseLabels、逐节点 epoch 与串行标记，并同时测完整时间、RSS、页池增长和质量。
3. 同网查询存在可见占比，但当前热点是搜索中的 owner 查询，不是 `gatherShareSet`。此前哈希索引负结果仍成立；任何新索引须纳入构建、增删与提交成本。
4. 当前没有跨价格版本距离复用、GPU/FPGA 实现、异步提交协议或硬件收益结论。保留设计级历史/占用、同网引用和 epoch 回绕语义。

## 复现

```bash
# 已有冻结 RRT 可直接从编译开始；重新导出需要本机已登记的真实输入和公开运行时。
python3 adapters/prepare_real.py
python3 adapters/build_real_router.py
python3 scripts/run.py profile-real
python3 scripts/analyze_real.py results/real_trace_<新时间戳>
python3 scripts/capture_tail.py results/real_trace_<新时间戳>
python3 -m unittest discover -s tests -v
python3 scripts/run.py check
python3 scripts/run.py smoke
```

`profile-real` 和 `capture_tail` 拒绝覆盖已有结果目录；主运行要求真实输入、构建输入与二进制哈希匹配，输出或收敛差异会失败。报告目录同时保留失败日志，不把失败改写为成功。原始参考和其他方案未修改。
