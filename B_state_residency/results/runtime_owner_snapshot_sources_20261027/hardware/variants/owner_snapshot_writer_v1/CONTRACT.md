# Incremental owner snapshot producer

The destination must already contain an exact immutable baseline clone. The producer tracks every accepted source AW range since that baseline epoch, deduplicates 64-byte lines, and refuses an overflowing dirty table or a failed/malformed source-write epoch. It observes the existing single-outstanding owner writer, not arbitrary concurrent DDR masters. It conservatively marks whole AW beats irrespective of WSTRB, including writes later reverted.

A native command captures source/destination/span/cookie under a held checkpoint lease and retired source transactions. Each dirty line is read from work DDR, written through independent AW/W handshakes, retired through the actual B reply, then read back and compared byte-for-byte. Only all-line verification creates a receipt. Missing lease, overlap/layout errors, table overflow, source B error, source R error, destination B error and verification failure cannot create a receipt. Loss of lease stops after already exposed R or AW/W/B transactions retire; it does not fabricate completion or mask in-flight VALID. No watchdog forces early completion when a slave permanently withholds its response.

owner_snapshot_checkpoint_adapter implements the lease-release and manifest gates in RTL: command/busy/held reply blocks lease release and manifest permission; after successful reply retirement a verified receipt permits publication. A later source AW invalidates the receipt. The current integration binds one fixed G1→G2 layout; this is not authenticated generic namespace binding. Source B error poisons this cumulative epoch; rebase/clear after repair is not implemented. A new baseline epoch needs a coordinated fresh baseline clone and tracker reset, not a silent clear of dirty addresses.

The unit uses MAX_DIRTY=4 and exercises 11 transactions/66 held-reply checks: empty epoch, deduplicated two-line copy with command-pin changes, no lease, in-flight source-R and destination-B cancellation, source R error, destination B error, verification R error, dirty capacity overflow, observed source B error, overlapping windows. Actual AXI bytes/errors are independently replayed. MAX_DIRTY=64 is used in the current real routing integration, which dirties four lines. No synthesis, timing, area, persistent integrity or board acceleration result is implied.
