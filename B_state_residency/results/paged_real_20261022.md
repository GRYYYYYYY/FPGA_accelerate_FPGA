# 真实分页 / 逐节点 epoch 消融（2026-10-22）

逐节点 epoch 已接入真实路由器，三次重复中，同序串行分页的布线耗时下降 **42.2%**，固定批处理配置下降 **30.3%**。两种标签实现在同一调度下的结果与收敛过程逐字节/逐轮一致，独立图验证通过。

其耗时仍为原始串行标记的 **1.36 倍**，并增加 epoch 标签内存；本轮证明的是相对原始分页的完整 CPU 路径收益，不是超过最快串行基线或 FPGA 加速。

## 输入与受控改动

沿用 [真实轨迹实验](real_trace_20261022.md) 的 logicnets_jscl / xcvu3p 冻结 RRT：9089009 节点、27960 个 net、180326 条间接连接；输入 SHA256 `d03de37af1a4a0b10f8bb29812b0048c4d2dd57ba6dadb70f61853225e39b6f4`。原始参考与其他方案未修改。

`adapters/build_paged_router.py` 从固定 SHA256 源码生成本地副本。两种分页共用相同页表、512 节点页、2048 页初始池、倍增和批处理回收策略。唯一主要策略差异：原始分页在每次查询第一次触页时清零整页；候选为物理槽位增加 uint32 epoch，仅在节点第一次访问时清零。每次搜索失效，绝不跨价格版本复用距离。全局 dyn 中历史价格与 net 占用保持原路径。

串行适配沿用原有连接顺序、搜索、代价与提交，仅每次查询 reset 分页状态并将 source.prev 设为 -1（与原始 batch 入口一致）。原始 CPU 标记二进制另作实际基线。

批处理复用原始 CPU 路径：1 个 partition worker，4 个 batch worker，批宽 8，仅迭代 3–8 且 overused≥128 时启用，rollback 开启、bounce=0、预算 1048576。RRT1 已有完整 CSR，但原代码只由 JNI/GPU 加载器置 flatGraphBuilt；本地适配在检查邻接边界后置该标志，使实际 batch 入口可用。此适配对两种分页相同，没有改批成员选择/提交次序。

CPU Xeon Gold 6530；串行绑定 CPU 8，批处理限制在 CPU 8–12，关闭原程序自行跨 NUMA 绑核。每种配置三次，按固定随机种子在每个重复块内打乱五种配置，逐个进程运行。所有性能程序关闭逐访问计数。每次重新加载，文件缓存未清除；无独占机器或固定频率保证。

## 正确性与调度差异

三个串行变体的全部重复均为 `428fa84ffa9e9839965c5000a32a4078f2fc7ea3f787a50cd4f7aff57447aa84`。两种 batch 变体的全部重复均为 `f2ac22fa156801e872a102687a865ea4516d76fba28cddd92fb483cfdbba98ec`。所有运行最终零过用、零未布通；同模式下比较逐轮 overuse、rerouted 等计数，任何差异都会中止矩阵。

批处理与串行的搜索/价格顺序不同，结果属于两个独立比较组。串行 totalLen=268901，batch totalLen=270395，差异 **0.556%**，不能把跨组差异归因于 epoch。totalLen 不是布后时序指标。独立检查全部连接的端点、图边、环路和跨 net 资源冲突，均通过；尚未回写物理设计或做 Vivado DRC/时序验证。

原始 batch 日志的 pops/conn、noFloodPath 在无 CUDA 编译分支未累计，出现 0 不表示无搜索；本报告不使用这些字段推导工作量。
