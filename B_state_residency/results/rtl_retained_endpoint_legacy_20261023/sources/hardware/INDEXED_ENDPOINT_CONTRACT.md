# 有界目录索引与完整状态端点组合

新增 `backing_page_service_indexed`、`record_backing_service_indexed`、`memory_scratch_endpoint_indexed`。它们是已验证宽codec服务/端点的机械变体，只改模块引用、透传索引参数；所有状态转换、公开命令、记录流、AXI操作、COMPLETE→RETIRE→RECYCLE顺序均保持原样。

默认23,405 frame、32K桶、64次探测、8位epoch。索引源为上一轮冻结的 `backing_frame_directory_indexed`。冷启动清表期间，上层可接受单个命令并在内部等待目录ready；不能返回未完成命令的成功响应。回绕清表必须一直受顶层fence_open保护，RECYCLE回复完成前禁止新的query。索引不参与页数据解释或published副本。

复用父版本small/actual测试和相同真实vectors/pages。small使用4 frame、4桶、1次探测、2位epoch，强制碰撞回退和回绕；actual保留512 frame的原语义实例，使用默认32K桶/64次探测/8位epoch以计入生产配置的初始化成本。默认容量整体综合另用23,405 frame。

验证代码仅改变模块/参数、增加只读索引生命周期观察器，并将单命令响应watchdog从30000周期增加恰好一张索引表的清零时间。该变化来自新架构确定的最大清表延迟，不改变任何期望值、协议检查、故障处理、响应背压或AXI时序模型。small的fence间隙周期可能改变，应作为测量值报告；公开命令/传输/错误/总线数量必须与父版本一致。

周期观察器仍被动采样原21个顶层状态，目录扩展为15状态。初始化清表全部纳入非reset总周期，即使与普通页命令重叠，也不额外加总重叠模块周期。另用独立开放寻址模型预测目录探测、权威owner读取、回退扫描和分配次数，与RTL状态计数核对。

本轮只验证19个真实小查询的完整状态存储路径，并比较同一10ns行为时钟下的周期；大查询完整RTL传输、整个搜索路由器、物理平台/实卡时序与性能仍待验证。已有时钟壳实验中的时序问题不会因行为周期减少自动解决。
