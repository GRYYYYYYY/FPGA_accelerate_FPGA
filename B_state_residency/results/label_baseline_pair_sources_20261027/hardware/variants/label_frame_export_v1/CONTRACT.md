# Native frame enumeration and runtime label snapshot

The authoritative directory exposes a new read-only sideband, disabled by default with ENABLE_FRAME_SCAN=0. A single request latches a physical frame, uses the existing synchronous owners RAM read path, and returns status/frame/owner27/published. Normal directory commands cannot overlap a pending scan or held scan reply. No allocation/index/lease/transaction-floor writes occur. Out-of-allocation returns UNREADY=6 without reading uninitialized RAM; missing permit, active memory leases or directory fault returns BUSY=2. Published/owner data remain stable through reply backpressure.

Eleven generated production files carry this interface along the active priced-core hierarchy. The query root additionally requires actual pc_owned, pc_safe, no warm ownership and no publication ownership. The pager additionally requires resident_page_manager.snapshot_clean: active, idle and both valid/dirty slot masks zero. Thus ordinary AXI retirement alone cannot authorize a stale DDR label snapshot. The integration first tests a nonempty-resident rejection, then uses the native control(1) flush/release acknowledgement before obtaining the actual PC lease and capturing.

label_snapshot_reader enumerates physical frames until the directory returns UNREADY (or FRAMES reached), filters owner27 by the selected query/price, rejects selected unpublished pages, reads three real 64B AXI beats per selected 192B page, validates padding and node bounds, and emits each present record as node32+payload160. Output order is physical-frame/slot order, not canonical node order. CRC32/IEEE covers the accepted little-endian node+five payload words; the successful completion supplies record_count/page_count/CRC. Partial/error streams are invalid until a successful completion. All exposed scan/AXI/record VALID offers retire before cancellation completes.

label_snapshot_checkpoint_adapter blocks checkpoint lease release and manifest permission for a pending command, operation or held reply. A successful retired receipt joins the existing owner-copy receipt before G2 publication. The stream is captured through actual handshake outputs into the trusted host artifact used for warm restoration. start_count comes from the native completed record count, not a CPU-selected recovery label list. This stream interface is not a persistent DDR snapshot writer.

The real 32-slot/one-slot integration enumerates 403 selected published frames and 822 records, 1209 AXI read beats, and then exercises native G2 publication, the second q180328 owner-B error, two-key G2 repair, 822-record warm restore and higher-attempt retry. Independent audit checks each directory reply, DDR byte, stream record, source CRC, consumed restore row and final state. The initial 822-label CPU future read-closure preload remains; this work replaces the later recovery-file source, not whole-graph initialization.

The unit exercises actual directory RESERVE/PIN/MEMORY_DONE/RETIRE setup, readonly inspection, held-response exclusion, invalid/denied scans, preserved TX floor, context filtering, stream backpressure, unpublished selected page, R error, in-flight R and scan-backpressure cancellation, and malformed padding. 102 response checks plus actual held stream cycles are independently audited. Default-disabled full integration preserves 16 old baseline files including all 8 AXI logs,7 DDR files and complete native trace/cycles.

Trust/limits: one coordinated checkpoint epoch and fixed context; initial G1 clone, historical path metadata and initial CPU read-closure still external. Descriptor/source-version authentication, persistent floors, arbitrary price changes/epoch wrap and running owner-baseline rearm are not proved. The exported CRC is independently audited; the existing trusted label_restore_controller does not yet enforce that selected source CRC in hardware. Extra masters use coherent shared-file DDR agents, not a board interconnect. No synthesis, timing or board acceleration claim.
