# 事务归属、恢复围栏与静态输入切片

本轮新增transaction_fence并接到真实RTL服务组合，替换测试台对正常准入/回复归属的直接门控。16个主机入口包括六配置、control、design、label、owner、cost-center、expand、frontier、cost及两个可信管理入口。普通主事务和192位route请求先缓存，再暴露后端VALID；请求被接受后前端输入变化不能改写后端payload。回复按已接受事务的归属退休，所有在途请求/回复和物理后备未排空前不交给恢复。

恢复请求先关新父事务。expand可能需要cost-center或nonhost cost续接才能完成，因此仅允许当前父事务的这两类续接排空；host cost仍为普通独占主事务，nonhost不能单独启动。父回复VALID一旦暴露，不因续接撤回；即使前端先消费父回复，后端父ACK仍等待已接受续接退休，以保留operation_pending上下文。此依赖边界用注册mock测试；完整正常搜索在新fabric下仍须回归。

恢复接管期间16入口及route均关闭，六配置/control/label/owner回调按端口并行记录pending与回复归属。七个现有单挂起AXI接口都接drain观察器；完成需要无回调pending、无新VALID、物理排空与后端idle。失败保持BLOCKED，不把背压当取消完成。所有权账本normal_retired与后端真实idle、物理排空分开。
