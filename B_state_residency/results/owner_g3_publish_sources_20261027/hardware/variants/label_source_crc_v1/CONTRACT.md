# Selected source label CRC binding

Opt-in CHECK_LABEL_CRC=1 propagates through query/search/residency to CHECK_SOURCE_CRC in label_restore_controller. All defaults remain zero. snapshot_label_crc is captured together with design/checkpoint/cookie/count/nodes/probe at the actual backend recovery acceptance; label_restore_controller captures that held value again on its own start handshake. Later changes to the external CRC pin cannot reselect the source image. lr_source_crc exposes the checksum of accepted source records.

The CRC is CRC32/IEEE, reflected polynomial edb88320, initial ffffffff and final complement. Each ordered record contributes little-endian node32 followed by the five payload32 words, identical to the native label_snapshot_reader stream. Correct format/cookie/count checks precede the aggregate check. At the last accepted source record, a mismatch returns new native label status8 before writing that last row or entering checkpoint/readback verification. Earlier rows may already have been written: failure is quarantine, not rollback. Existing write/readback and physical retirement checks remain necessary after CRC success.

Real positive 32-slot/one-slot experiments use the actual exported source CRC (a2b92ed0/9ae2e09b), change the CRC pin after recovery acceptance, and still restore/readback-verify all822 rows, consume real label/path/query receipts, then retry q180328 under4/2/4. Independent audit recomputes source bytes, verifies the actual CRC reply, all10 AXI streams, final owner/labels and CPU search oracle.

The full 32-slot negative selects CRC xor1 before acceptance. All822 source records are accepted; only821 are written, none verified. Actual native status8/CRC matches the original stream, coordinator returns6 retaining journal2 and G2/CP18 owner image. No successful label/path/query receipt or query retry occurs. Completion consumption leaves warm owned/fault and business closed. The test only permits this expected fault in its healthy-owner assertion; no DUT handshake or payload is masked. The first negative development run stopped on that old healthy-only assertion after the correct native status8.

Unit RAM-backend cases independently recompute zlib over accepted records and check actual field writes/control commands/read counts: correct CRC despite changed input pins; wrong expected CRC; one-bit payload corruption; row permutation. Enabled mode has32 held-reply checks; default-disabled mode has16 checks and preserves trusted-stream behavior even with a wrong CRC argument. Full default-disabled runtime snapshot/G2 warm integration is compared byte-for-byte to the prior baseline:10 AXI logs,7 DDR files,native trace and label stream (19 files/cycles).

CRC is integrity, not authentication. The selected descriptor and bootstrap context remain trusted; no persistence, signature or collision resistance is claimed. Initial CPU label read closure and G1 clone still exist. Failure-after-CRC non-cold retry, owner epoch rotation, unknown-page initialization, arbitrary price changes/epoch wrap, real overflow allocation/reclaim, synthesis/timing and board gains are not newly proved here. Compatibility covers the repository's named parameter/port instantiations, not arbitrary external positional instantiations.
