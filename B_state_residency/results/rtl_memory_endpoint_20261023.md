# 页槽—AXI后备存储—双域回收的闭合RTL端点

2026-10-23：`memory_scratch_endpoint` 已通过小位宽边界仿真、19个真实小查询的完整字段回放、七项故障对照、默认容量整体综合及最终审计。EXPORT/BEAT/COMPLETE、地址RETIRE和RECYCLE均由顶层RTL生成，外部不再提供完成或排空声明。

该顶层是状态存储端点，尚不包含完整FPGA搜索/布线路由器。没有布局布线时钟闭合、真实DDR/HBM平台或实卡加速结果。

- [顶层RTL](../hardware/rtl/memory_scratch_endpoint.sv)、[接口契约](../hardware/MEMORY_ENDPOINT_CONTRACT.md)。所有旧模块保持冻结；新增顶层组合页槽、页控制器、有界队列、记录级存储适配器、codec、后备目录和AXI引擎。
- [manifest](rtl_memory_endpoint_20261023/manifest.json)、[最终审计](rtl_memory_endpoint_20261023/completion_audit.json)。manifest SHA256：`6c22b2762a8e22dbfeb940ac41727c65aa2caf2e5f68e1c0a0061380535ecccb`。
- 最终源码冻结于 `verified_build_v2/sources`；完整MCP仿真记录分别在 `small_final/session.log` 和 `actual_final/session.log`。
- 外部仅接受QUERY/BIND/READ/WRITE/RELEASE/WB/RF/BEGIN_FENCE/FINISH_FENCE。新增4位响应状态区分后备未就绪、容量满和IO故障。

写回按“地址RESERVE→页槽WB事务→64次EXPORT确认→成功内存响应→页槽COMPLETE确认→地址RETIRE确认”执行。读取按“LOOKUP已发布页→页槽RF事务→内存成功及格式校验→逐条BEAT确认→成功内存响应核验→COMPLETE确认→RETIRE确认”执行。最后一条记录握手不会代替最后BEAT的成功响应。

FINISH_FENCE先等待页槽及其全部内部队列完成排空，然后回收后备地址目录。`fence_open` 跨两阶段保持全局draining，直到后备分配数/租约清零、RECYCLE成功才返回。外部响应被消费前不接受新命令，覆盖两域回收之间的事务号/地址复用间隙。

小位宽测试覆盖有限事务耗尽、槽代次不能提前复用、query ID隔离、未知后备页refill不分配地址、后备容量满、脏页不能释放/排空、空页与present-zero区别、NaN payload与负零保持。它在两域回收间隙主动持续提交新QUERY，确认在旧FINISH响应被消费之前无法接受，然后确认新query/gen/tx可以从0开始复用。

9类故障包含既有8种总线错误和“总线成功但页尾损坏”。AXI读错误排完已接受burst后返回，未发布不完整页；顶层不发COMPLETE/RETIRE，页槽与地址租约均保留。故障后的READ、RELEASE、外部COMPLETE和FINISH全部拒绝。对未知内部协议故障的通用恢复仍未实现，IO_ERROR不能普遍作为总线已静止的证明。

真实回放使用[原始字段捕获](real_field_values_20261023.md)中全部19个小查询，共56,588次实际字段访问。之前页控制器的472,689条命令中，内部EXPORT/BEAT/COMPLETE被折叠进6,086个外部WB/RF命令；公开命令剩77,099条，包含2,702次WB、3,384次RF、7,184次绑定与7,184次释放。

原内部传输记录仅用于生成独立预期AXI字节，**不作为新顶层的记录输入**。外部只输入普通字段写入和控制命令；从设备模型在写突发完成时保存实际DUT输出字节，读取时从该内存返回。全部写/读数据拍与独立预期逐位比较，字段响应继续与原始记录值oracle比较。最终审计独立遍历旧命令、全部新命令及127,806个预期页拍，验证投影、owner/frame映射和字节序，无跳过原字段访问。

实际回放后备映射峰值390页，512-frame实例足够；所有64种4KB起始偏移均出现。仍未回放另外19个超过100,000次访问的大查询，也未重新执行完整570,286次搜索的路由算法。

边界与真实仿真结束时间分别为820,130 ns与105,164,880 ns。后者对应测试台10 ns周期下约1,052万周期，包含确定性队列/总线背压和响应等待。它不是实际FPGA运行耗时，也不能与原CPU完整路由秒数作加速比较。

## 故障注入对照

七个变体均成功编译和展开，并在运行期检查处失败：

| 变体 | 检测点 |
|---|---|
| 内存完成前发COMPLETE | 内存成功与64条记录确认不足 |
| 页槽完成确认前发RETIRE | 地址退休顺序错误 |
| 最后一条BEAT只等命令握手，不等响应 | 只有63条记录确认便发COMPLETE |
| 省略后备RECYCLE | fence流程未到达地址回收阶段 |
| 忽略fault封锁 | 错误后READ返回BUSY而不是IO_ERROR |
| 接受外部COMPLETE | 内部完成顺序断言立即检出未经授权的完成 |
| 回收过程中提前开放cmd_ready | 新命令可能早于后备地址回收 |

首版driver对第6例预计观察外部状态不符，实际更早触发了内部完成顺序断言，按分类不符停止；其失败manifest和全部已运行日志保留。新版核验并继承六个已完成失败轨迹，修正分类，只运行最后一例及综合。没有修改RTL、测试台或放宽断言。早期边界仿真仅出现cycle声明位置提示，移到使用前后重新运行，结果完全相同；旧日志保留在 `small_pilot`。
