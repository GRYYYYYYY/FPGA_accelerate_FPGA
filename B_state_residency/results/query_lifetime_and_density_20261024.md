# 查询生命周期边界与页记录密度（2026-10-24）

四查询保留测试和真实页密度普查均通过。默认 RTL、已发布 6 位源包、活动 16 位全量回放及冻结输入均未修改。当前仍没有完整 FPGA 路由器或板上加速结论。

## 生命周期实验

`hardware/scripts/make_query_lifetime_tb.py` 从已有自检 TB 保留 AXI 字节、响应稳定、逐记录确认、COMPLETE/RETIRE、租约和 fence 监测，生成独立测试。`run_query_lifetime.py` 对静态 codec、记录响应旁路的同一冻结 RTL 分别配置目录 EPOCH_BITS=6/16；其他 TX/GEN 均 16 位、TAG=2、32 帧、hash6。每版 56 项检查、8 次成功 WB/RF、1 次完整回收、0 次成功 CHECKPOINT，独立源码绑定审计通过。

四个 query ID 各访问同一页 42，写入不同有效记录并写回、释放、重新绑定和读回；后备分配数依次增加至 4，后续 query 的首次 REFILL 返回 UNREADY 且不发起 AXI 读。该证据说明地址相同不使后备归属跨 query 别名。每版两个非独占 CHECKPOINT 均拒绝，已使用 ID 在相同价格或新价格均 EXHAUSTED。错误旧 query 的 BIND 返回 STALE。完整 fence 清空后备归属后，query ID 和 generation 可从零重用；旧后备不可见，驻留标签为空。

这只证明有界四查询控制路径，不证明无限 net 生命周期批处理可行。已使用 ID 仅在完整 fence 后释放，事务与 generation 预算也必须管理；多查询后无法使用现有保留后备的 CHECKPOINT。在线准入须知道查询的资源上界或提供可证明的回退协议，不能只按相同 net/价格共享距离标签。此次未额外测试旧 query 的 REFILL 命令或整个真实设计的多查询调度。

结果：`results/query_lifetime_20261024/manifest.json`、`source_bound_audit.json`。两个仿真均在 18420ns 正常结束，FINISH 重试为 0；不能据此推断所有负载无需合法 FENCE_WAIT 重试。
