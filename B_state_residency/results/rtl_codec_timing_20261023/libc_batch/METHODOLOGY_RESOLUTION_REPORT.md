# OOC配对实现的方法学检查

Vivado 2022.2；AMD timing-methodology-checks技能要求2026.1+。本轮读取其检查原则及TIMING-18说明，并通过本机help核实支持的命令，使用 `report_methodology -file` 文本报告。没有使用不支持的 `-json`。

本阶段是冻结网表比较，不是平台时序收敛。约束来源为 `hardware/rtl/scratch_frame_store.xdc` 第2行，只有 `create_clock -name core_clk -period 10.000 [get_ports clk]`。两版实现前后的可执行XDC内容逐行一致。没有约束修改，因此没有约束diff或豁免。

| 检查 | 原版综合后→实现后 | 宽版综合后→实现后 | 处理 |
|---|---:|---:|---|
| TIMING-18 | 1000→1000 | 1000→1000 | 保留；未提供平台接口时序 |
| no_input_delay端口计数 | 624→624 | 624→624 | 保留 |
| no_output_delay端口计数 | 788→788 | 788→788 | 保留 |
| 无时钟寄存器 | 0→0 | 0→0 | 无该项问题 |
| 未约束内部端点 | 0→0 | 0→0 | 内部路径已检查 |
| 实现后RTSTAT-10 | 1条、246条网络 | 1条、246条网络 | 保留；检查真实上层连接 |

两版均有HD.CLK_SRC未设置的警告；真实时钟延迟/偏斜未建模。真实平台接口预算及上层时钟位置尚未确定，本阶段不填入任意假设使警告消失。没有USER类约束修复、AUTO约束修复或waiver。内部WNS/WHS为原版4.395/0.036 ns、宽版4.280/0.016 ns；这不构成完整平台建立/保持时序证明。

详细数据、限制、兼容性诊断和下一步见 [配对实现报告](../../rtl_codec_timing_20261023.md)。审计通过代表文件和数据提取一致，非所有方法学问题已解决。
