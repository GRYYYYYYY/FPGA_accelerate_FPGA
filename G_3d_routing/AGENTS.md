# 方案 G 工作上下文

- 本目录研究：三维跨层资源选择与分层搜索。研究问题：针对离散固定的跨层资源，候选端口选择和局部搜索能否改善三维布线的求解时间与质量？
- 优先阅读 README.md、EXPERIMENTS.md、INTERFACES.md、NEXT_STEPS.md。原始论文与公共参考源码位于上级目录，路径已列出。
- 已接入固定 VTR 原始 CPU 模型基线、完整 RRG 的 SQLite 投影和路由审计，见 results/BASELINE_REPORT.md。保留 Python toy；GPU/FPGA 与完整候选算法比较未实现。模型验证不等于真实器件适配；不要将样例逻辑计数或排程估计解释为实测加速。
- 用户要求吸纳其他场景的成熟方法以提高可实现性；不能仅因方法已有基础就排除创新可能，也不能未经比较宣称新颖或保证收益。
- 当前优先任务：基于已冻结 RRG 和基线实现离线候选端口评估与有向可达性验证，再比较相同布局/目标下的原路由器、简单垂直惩罚和 CPU 候选选择。原生 CHANZ 是共享有容量节点，不能直接套用 toy 的垂直边容量语义。
- 可运行 python3 scripts/run.py baseline；版本、运行库及输入哈希见 configs/vpr.lock.json 和 data/raw/ex5p_*.json。本轮两种布局各 3 次、seed=1；原布局是端点跨层负对照，balanced 是人工压力布局。勿把相邻工程的改动程序冒充 original_vpr。
- 原始参考源码保留在 `../_shared/assets/gpu_router_original/` 和 `../FPGA-Routing-main/`。本方案改写与适配放在本目录，避免无意改变其他方案的基线。若需公共改动，说明影响并运行受影响目录的检查。
- 沿用上级 AGENTS.md 的 FPGA/AMD 工具规则：按任务选择并阅读 Ross Skill；纯算法/代码/文稿任务无需启动 Vivado。实际 Vivado 操作优先检查并使用现有 MCP 会话，默认 Tcl 无 GUI；默认版本 2022.2，先核实新功能支持。
- 在已有授权内自主推进，不把实验阶段或文档中的待办项当作额外审批要求。

本方向重点语义：

- 只选择架构已有的垂直连接，不能自由移动或新增 HBT。
- 普通多金属层 ASIC 图、商业多 SLR 器件和堆叠 3D FPGA 模型应区分。
- 跨层次数更少不必然时序更好，需要联合延迟与拥塞评价。
- 模型化 RRG 验证不等于真实三维工艺签核。
