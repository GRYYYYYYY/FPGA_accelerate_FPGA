# 方案 G 实验设计

## 工作假设

针对离散固定的跨层资源，候选端口选择和局部搜索能否改善三维布线的求解时间与质量？

对照层次保持分开：已有方案、成熟方法的直接迁移、当前场景的适配方案；同时区分软件算法改动与 FPGA 执行收益。可以让本方向单独成为论文主贡献，不要求拼齐其他所有方案。

| `fpga_portal_eval` | 同一算法 FPGA 候选评估 | 待实现/接入 |

## 消融变量

2026-10-22 已完成的基线接入及本轮结果见 [BASELINE_REPORT.md](results/BASELINE_REPORT.md)。当前最小批次固定 seed=1、W=100，两种布局各重复 3 次；原布局的端点跨层连接为零，因此作为负对照，人工平衡布局用于跨层语义验证。它们不能互相充当算法收益对照，算法对照必须使用同一份 placement/RRG。

`configs/experiment.json` 的 `status=planned` 保留共享脚手架的矩阵枚举兼容性；原 VPR 另有 `standalone_status=implemented_model_baseline`。本目录 `plan` 已明确列出两条可执行基线，其余变体仍不可执行。全局配置的 seeds 1/2/3 是后续矩阵目标，本轮仅 seed=1。

- 垂直资源密度与分布
- 跨层延迟与容量
- 层数和 net 扇出
- 端口候选数及分层搜索策略

先选能够回答主假设的最小对照，不强制穷举组合。交叉实验应检查相互作用，例如压缩与驻留、驻留与调度、内存后端与数据布局。

## 指标

| 指标 | 单位 |
|---|---|
| `routing_ms` | ms |
| `critical_path_delay` | ns |
| `routed_wirelength` | tool_unit |
| `vertical_resources_used` | count |
| `overflow_resources` | count |
| `routing_success` | boolean |

计时分别记录准备/构图、首次加载、状态初始化、内核、结果回溯、提交/同步、回退和完整流程。首次运行与驻留复用运行分别报告。硬件有效频率以实现报告/实际运行配置为准；CPU toy 的逻辑次数不换算成硬件周期或速度。

## 阶段验证

1. 接通真实软件基线，固定输入、工具/代码版本、环境变量与约束。
2. 接入真实数据接口，先验证与源工具的资源和结果语义一致。
3. 实现直接迁移的软件原型，复现和分析无收益案例。
4. 实现本方向的场景适配机制，与相同算法目标的基线比较。
5. 接入硬件并进行仿真/综合/实现或实卡验证，记录实际覆盖范围。
6. 回到完整布局/布线流程，检查质量、成功率、迭代变化和端到端收益。

这些是可复用的推进顺序，并非审批流程。根据已有授权与具体研究进展可以调整。

## 必须保持的语义

- 只选择架构已有的垂直连接，不能自由移动或新增 HBT。
- 普通多金属层 ASIC 图、商业多 SLR 器件和堆叠 3D FPGA 模型应区分。
- 跨层次数更少不必然时序更好，需要联合延迟与拥塞评价。
- 模型化 RRG 验证不等于真实三维工艺签核。

## 可重复性与结果边界

真实结果保存数据哈希、代码版本、完整命令、设备/驱动/平台包、随机种子、重复次数和计时范围。`configs/experiment.json` 中尚为空的阈值和版本必须按真实实验填写，不能把 null 当作零。

相同输入与约束下比较，并报告失败、预算耗尽、回退及完整流程结果。若主张时序质量，需加入布后时序或经过验证的时序模型；线长不能代替时序。当前合成样例结果不能纳入正式论文性能表。
