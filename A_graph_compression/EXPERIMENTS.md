## 工作假设

压缩资源图能否在保持规范节点、边和资源属性一致的前提下，降低真实搜索的访问成本或扩大可处理规模？

对照层次保持分开：已有方案、成熟方法的直接迁移、当前场景的适配方案；同时区分软件算法改动与 FPGA 执行收益。可以让本方向单独成为论文主贡献，不要求拼齐其他所有方案。

基线：Vivado 显式导出记录；对照：按 `(源 tile 类型, 规范 wire 名)` 分组，以样本内众数邻接规则为模板。PIP tile 使用相对网格坐标，端点通过完整 wire→规范节点表解析；节点不能按坐标或模板合并。删除例外先于解析，保留并行边多重性、每个 PIP 的身份、遍历方向和所有导出属性。节点属性目前不压缩。

去掉实例例外后，169 个源节点失败：86 个连接规则不同、83 个仅属性不同；85 个不能在已导出域中解析，84 个可解析但内容错误。属性差异包括 `SPEED_INDEX`、`VORPAL_ID` 及导出的入口/出口分组索引。这里“连接规则”包括相对 tile 位置，不能仅据此推断电气拓扑改变。

注入覆盖：丢掉一条平行边、错误反向遍历、修改 PIP 速度索引、擦除 pseudo 标记、修改节点 intent、重复有向 PIP、保持边数但改 PIP 身份、损坏独立 oracle、错误合并跨 tile 别名、漏掉例外、删除不存在的模板规则。占用测试验证同一规范节点的跨 tile 别名共享状态、共用模板的不同规范节点状态独立。

边界：样本内拟合后还原并不证明未见区域的泛化；4,471 个目标节点未展开，67 个源节点经查询确认为无出边。未覆盖 excluded PIP、真实网表保护与占用、完整搜索、时序质量、硬件。计数不等于存储字节；完整表、元数据与索引仍有成本，所有性能字段为 null。下一步才建立打包布局与受控的实际搜索对照。

## 阶段验证

1. 接通真实软件基线，固定输入、工具/代码版本、环境变量与约束。
2. 接入真实数据接口，先验证与源工具的资源和结果语义一致。
3. 实现直接迁移的软件原型，复现和分析无收益案例。
4. 实现本方向的场景适配机制，与相同算法目标的基线比较。
5. 接入硬件并进行仿真/综合/实现或实卡验证，记录实际覆盖范围。
6. 回到完整布局/布线流程，检查质量、成功率、迭代变化和端到端收益。

这些是可复用的推进顺序，并非审批流程。根据已有授权与具体研究进展可以调整。

## 必须保持的语义

- 不同物理资源即使模板相同，也必须拥有独立的动态占用。
- 跨 tile 的同一物理导线必须映射到同一规范节点；不要只按坐标合并节点。
- 保持并行边、开关方向、属性和特殊资源语义；不能只比较边数。

## 可重复性与结果边界

真实结果保存数据哈希、代码版本、完整命令、设备/驱动/平台包、随机种子、重复次数和计时范围。`configs/experiment.json` 中尚为空的阈值和版本必须按真实实验填写，不能把 null 当作零。

相同输入与约束下比较，并报告失败、预算耗尽、回退及完整流程结果。若主张时序质量，需加入布后时序或经过验证的时序模型；线长不能代替时序。当前合成样例结果不能纳入正式论文性能表。

## 已执行：冻结模板、四跳域与 CPU 搜索（第二轮）

入口为 `python3 scripts/run.py region-check`，固定配置见 `configs/region_query.json`，最终报告为 `results/region_check_20261022_v2.json`。代码、原始数据、配置、派生图、冻结模板库及完整搜索轨迹均有 SHA256。

训练只使用首轮数据中规范源节点位于 SLR0 的 384 行；拟合 110 个模板并冻结后，才加载评估文件。SLR1/2/3 留出数据按实际 `SLR_REGION_ID`、物理上下边界行和资源类型取 36 个 seed tile，共 828 行。两组规范源节点无交集；边端点和别名可以跨 SLR，不能视为独立器件测试。

| 留出分类 | 源节点数 |
|---|---:|
| 无例外精确还原 | 478（57.7%） |
| 仅导出属性例外 | 183 |
| 连接规则例外 | 167 |
| 训练未见类型 | 0 |
| 带例外还原 | 828/828 |

留出样本包含 8,339 个规范节点、24,276 个别名、8,111 条有向边，25 个节点的别名跨 SLR。36 个 tile 中扫描了 62,136 个 PIP，excluded 标记命中 0；这只是该空设计样本的覆盖缺口，不能宣称器件不存在这类资源。

搜索域以 `INT_X0Y360/EE2_E_BEG0`、`INT_X0Y600/EE2_E_BEG0`、`LAG_LAG_X4Y539/UBUMP0` 为源。完整导出距离 0–3 的 229 个源节点的一跳邻接，得到 875 个规范节点和 1,076 条有向边；646 个距离 4 的节点保留为未知邻接边界。4,000 个展开节点的导出预算未耗尽。独立 Vivado downhill-node oracle 证明该深度范围完整。

12 个连通查询由上述真实资源各取距离 1–4 的目标构造；另设四个语义探针：预算耗尽、未知邻接、已确认 sink 的无路径、零跳。统一 FIFO BFS 使用每次 PIP 遍历代价 1，邻接按相同键排序，保留 PIP 身份及平行边访问。CSR、原始按需译码和预处理译码的 16 项结果/路径/展开轨迹完全相同。零跳以外的 12 个可达查询全部找到最短跳数路径；没有把未知边界视作 sink。26 项回归通过。

**覆盖负结果：** 搜索域只有 43/229 个源节点属于训练已知类型，其中仅 2 个无需例外；其余 186 个采用显式规则回退，保存 820 条规则。构建回退和例外使用评估真值，没有向冻结模板库学习新模板。“带补丁还原正确”与“模板可泛化”是不同结论。

**CPU 计时（7 次、驻留、无 trace 计时）：**

| Python 表示 | 12 查询批次中位 ms | 一次 provider 初始化 ms |
|---|---:|---:|
| 显式 CSR | 0.624960 | 1.063237 |
| 原始按需模板 | 20.956275 | 0.579373 |
| 预处理模板 | 2.890911 | 10.758953 |

三种 provider 每轮轮换先后顺序。先进行一次带 trace 的语义运行作为 warm-up；正式计时不含 trace、文件读取、模板拟合和例外生成。报告 `preprocessing_ms` 单列这些前处理阶段，provider 初始化也不藏入搜索核。以上只测同一进程的 Python 单位跳数 BFS，没有 CPU 固定绑核，不能当完整网表路由或板卡收益。

原始实现的独立 cProfile 显示热点为 `deepcopy`、`rules` 与 JSON 编解码；profile 本身不混入查询计时，累计时间存在嵌套，不能相加。预处理版在初始化时计算每个源节点要跳过的模板规则索引，查询时借用只读模板/add/fallback 载荷；未预先生成规范节点边数组，也未把 fallback 消失当成压缩。它比原始译码快，但仍慢于 CSR，且初始化更重。

下一轮应优先检验独立训练搜索轨迹能否降低未知模板回退率，再定义完整的紧凑二进制布局与属性补丁，而不是凭规则计数或此处 Python 比值决定硬件收益。

## 第三轮：搜索训练覆盖与 packed/native 对照

预登记见 `configs/traversal_v1.json`，不可根据新评估结果修改原配置。原始 capture 与独立 child oracle 证明深度 0–4 完整展开，深度 5 未展开；SLR0/SLR1–3 源隔离成立，评估源与前两轮无重叠。新域没有跨 SLR 导线，跨 SLR 语义仍依赖前两轮覆盖，不能说本轮验证了全部特殊资源。

本轮未覆盖真实网表路由、拥塞/时序约束、实卡带宽、端到端路由加速。完整目标必须继续完成 `EXPERIMENT_STATUS.json` 的其他项。
