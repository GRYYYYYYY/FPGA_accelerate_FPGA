# Mutable site ownership and history, v1

`search_site_occupancy_top` manages physical site resources for negotiated
routing. Production limits are 65,536 owner records, 65,536 retained history
keys, and 65,536 entries in a replacement request. Signals, masked bits and
categorical values use kinds 0, 1 and 2. Identity is `(kind, physical_id)`;
template identity must never substitute for physical identity.

The helper contains no dynamic allocation, STL, recursion or function pointers.
All interface pragmas are inside the top function. The CPU bridge allocates
backing vectors and exports observations; it has no second live owner/history
map. The independent reference remains `src/native/site_ledger.hpp`.

## ABI

All pointers must be disjoint, fully allocated and exclusively owned during a
call. Internal storage is trusted state generated by reset and successful
operations; arbitrary corrupted state is outside this contract. Integer words
are unsigned. Allocation depths below are words, not bytes.

| Buffer | Type/depth | Content |
|---|---|---|
| config | u64 / 8 | `[op, net, request_count, 0, 0, 0, 0, 0]` |
| meta | u64 / 6 | `[magic, owner_bank, owner_count, history_bank, history_count, version]` |
| owners | u64 / 524288 | Two banks, each 65536 rows of `[key,net,mask,value]` |
| history | u64 / 262144 | Two banks, each 65536 rows of `[key,cost]` |
| request | u64 / 196608 | 65536 rows of `[key,mask,value]` |
| flags | u32 / 65536 | Scratch conflict flag per active owner row |
| summaries | u64 / 131072 | Scratch `[key,conflicting_net_count]` rows |
| out_owners | u64 / 262144 | Snapshot owner rows, excluding requested net |
| out_history | u64 / 131072 | Snapshot of all retained history |
| result | u64 / 6 | `[status,owners,history,version,conflict_groups,snapshot_owners]` |

`key=(kind<<32)|physical_id`. Owner rows sort strictly by `(key,net)`;
requests and history sort strictly by key. A signal has mask/value zero; masked
bits require `value & ~mask == 0` (zero masks are retained); a categorical row
has zero mask and a uint32 value. Net/physical IDs include zero and UINT32_MAX.

Operations: 0 reset, 1 replace (empty request releases a net), 2 analyze, 3
advance history, 4 snapshot. Only replace uses request_count; only replace and
snapshot accept a nonzero net. Status: 0 success, 1 invalid, 2 capacity, 3
overflow. Reset sets empty banks and version 1, without clearing unused storage.
Every successful replace/advance increments version, including empty operations.
Read operations do not increment it. Saturated version rejects mutation.

Replace first validates the complete request and final owner count, then merges
into the inactive bank. Advance first analyzes conflicts and dry-runs the entire
history merge, checking capacity and every addition before any persistent write.
Rejected operations preserve both persistent banks, metadata and snapshot
outputs, including unused words. Scratch is disposable and may change. Result
is always overwritten; its last five words are zero on failure. Successful
snapshots write only their logical lengths; unused tails retain prior contents.

## Conflict semantics and cost

Different nets conflict on shared signals, unequal categorical values, or
incompatible overlapping masked bits. Compatible or disjoint masked-bit owners
are not automatically conflict participants. History increments by the number
of distinct participating nets minus one for each conflicting key. History
survives release. Snapshot rows match the existing production search packet;
the search component continues to compute present-plus-history penalties.

For each key, the helper aggregates required ones and zeros, then marks each
owner that conflicts with another owner. The reference uses pairwise comparisons.
Replace, conflict analysis, history merge and snapshot have linear work in
active owner/history/request counts. Replacement copies a bank; this is a
correctness baseline, not a throughput claim. Persistent banks occupy 6 MiB
plus metadata; complete declared buffers occupy 11.75 MiB plus 160 bytes.

## Verification scope

The native reference test runs 12,000 random operations, exact records/history/
conflict sets and snapshots, failure-state preservation, disjoint bit owners,
zero masks, late history overflow, version saturation, full production owner/
request/history limits and guards under ASAN/UBSAN. Full-router integration
uses the unchanged production search C model in both graph representations and
compares every intermediate search and negotiation round with the old oracle.

HLS 2022.2 uses a C++14 test-only pairwise oracle because the original native
oracle includes C++17 structured bindings. The generated testbench differs only
in that include; its hash and original test are recorded. C simulation and
synthesis do not establish RTL equivalence. RTL, physical implementation, XRT
integration and board throughput remain separate work. Complete physical site
semantics also remain limited to the previously validated resource instances.
