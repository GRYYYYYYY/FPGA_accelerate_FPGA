跨场景方法迁移矩阵

以下右侧内容均为本报告提出的迁移方案，不表示原论文已经实现了这些 FPGA 布局布线功能。

来源与原方法迁移到当前任务需要处理的差别
AccDRC：保留 cell 层次，局部展开与任务封装tile / wire 类型模板与实例参数分离；按需生成邻接；局部图页连续传输。同类资源可以共享描述，但不同物理资源不能共享占用；跨 tile 的同一物理导线必须保留统一节点身份。
DFMAcc：复杂度驱动分区、硬件容量约束以预估扩展边数、状态容量、更新冲突与传输成本决定搜索区域和任务批次。几何面积不能代表搜索难度；长线和跨区域节点不能被裁掉。
Sextans：片上随机访问、片外流式读取、PE 感知稀疏任务调度邻接块顺序读取，活跃搜索状态片上分块；按目标存储块组织松弛更新。SpMM 的非零结构可提前规划；搜索活跃集会动态产生，调度需要在线队列与依赖处理。
FlowGNN、ThunderGP：图计算分阶段数据流候选选择、邻接展开、代价计算、状态更新通过队列连接；支持可变出度和多连接上下文。路由具有优先级反馈与停止条件，不能直接把全图 GAS 扫描作为每次连接搜索的必经流程。
FlightLLM：片上保留中间状态、减少阶段间搬运按静态图、设计状态、net 状态、搜索标签的生命周期分层驻留，复用相邻查询工作集。图搜索状态不是固定尺寸张量；容量溢出、状态失效、稀疏性和多上下文隔离需要重新设计。
KV-Direct：键值操作、依赖跟踪与更新转发把节点状态与资源更新视为按 ID 寻址的操作流；合并重复更新，转发同一节点的在途最新值。单节点原子操作不足以解决整条路径的提交与同网共享计数，需要路由层协议。
DFMAcc 的过滤—验证组织先做方向、类型、资源限制和代价下界过滤，再访问完整状态；也可筛选布局候选后调用真实局部布线。保守剪枝需要有效下界；启发式裁剪应保留扩大搜索或回退的途径。
FBLAS：可组合流式数值算子；Sextans 的稀疏归约布局中的 pin/net 聚合、代价与梯度计算、位置更新串接，减少中间数组搬运。异构位置合法性、级联与区域约束仍需独立处理；密度求解器中的全局变换不能都视作局部 stencil。
低精度与混合精度加速窄位宽候选排序、代价区间估计、边界情况高精度重算；静态拓扑优先采用无损编码。代价量化会改变搜索顺序和协商收敛；路径合法不等于代价最优，需分别验证。
AutoBridge：物理划分与流水协同让存储块、搜索 PE 与内存通道就近放置，减少跨 SLR 高扇出通信。搜索反馈环的额外延迟可能降低单连接推进速度，需要多上下文或算法调度来隐藏。
H3D：异构跨 die 资源建模与树上动态规划在三维 RRG 上选择已有垂直端口，联合树分支共享、局部搜索与跨层拥塞代价。FPGA 垂直连接通常是离散固定资源，不能照搬 ASIC 中移动 HBT 位置的自由度。

七条可形成论文的候选路线

以下可实现性是根据现有软件和 RTL 基础给出的工程判断，不是对发表概率的评分。每条路线都可以选择一个机制作为主贡献，其他技术用于建立可靠实现。

A．面向直接搜索执行的资源图压缩

核心问题：能否把资源图压缩从文件存储或内存节省，推进到邻接生成、属性访问和搜索执行本身，使压缩后的图减少实际访问代价？

同学的 DeviceModel.hpp 已具有模板与例外数据、节点归一化和内存图重建；main.cpp 的 GPU 通道还会物化扁平邻接。这给出了明确的起点：先保留其语义，建立“CPU 模板展开 → CSR”的参考链，再尝试“FPGA 模板译码 → 邻接流”。AccDRC 的延迟展开可以迁移到这里，模板和例外表使用小型缓存，频繁访问的邻接块可以物化，冷块按需译码。

可能的主贡献包括：适合硬件生成邻接的资源图编码；模板译码与缓存的联合组织；压缩粒度与存储通道的映射方法。并不要求三者同时成立。已有 FPGA 资源图压缩研究提供了比较起点，但具体执行路径仍需逐项比较。

最小实验：从同一批真实 RRG 查询生成邻接轨迹，比对每个规范节点的邻接集合、方向、开关和属性；在相同搜索器上比较普通 CSR、已有模板展开、新表示的字节数、译码周期、随机访存次数与总搜索时间。模板压缩不能合并不同实例的占用状态，也不能漏掉例外、跨 tile 节点或受保护资源。

可实现性：软件验证较容易，硬件实现中等。若新表示只缩小文件但没有减少工作集、访问成本或提高可处理规模，可以调整其论文定位；这一结果本身不应提前假定。

B．按生命周期组织的驻留状态与迭代布线

核心问题：在大量短搜索和反复协商中，能否减少状态初始化、加载、回写和重复计算，使设备持续处理路由任务？

建议明确四类状态：①器件级静态拓扑与基础属性；②设计级占用、历史拥塞与已提交路径；③net 级路由树和分支共享关系；④connection 级代价标签、前驱、OPEN 状态和访问标记。分别选择板上 DDR/HBM、BRAM/URAM、缓存或按需页。状态驻留不意味着全图都放片上，例如一亿节点每节点仅 16 字节也需要约 1.6 GB。

可迁移 FlightLLM 的中间状态复用思想，以及 KV-Direct 的依赖跟踪、更新合并与转发机制。以搜索代次标记实现稀疏初始化，结合片上页分配、多上下文隔离、页回收及位宽回绕处理。已有 CPU 分页实现是直接迁移基线，而非排除该方向的理由。

另一条值得保留的分支是多接收端网络：复用已构建路由树、局部邻接与候选路径，降低每个 sink 的重复准备成本。跨连接或跨迭代复用距离标签需要满足代价与源集合条件，不能把旧距离默认当作当前搜索的有效标签。

最小实验：保持搜索算法一致，逐项比较全量清零、已有 epoch/分页方法、硬件驻留与稀疏初始化；分别统计初始化、状态访问、提交和迭代次数。初版 CPU 持有权威占用并发布增量，后续可研究设备侧资源所有权和提交。两者是不同研究深度，不应同时强制完成。

可实现性：状态生命周期与单连接实现中等；完整并发提交较难。若价格同步已很便宜，仍应检查初始化和状态访存，而非预设提交一定是主瓶颈。

C．面向工作集与共享资源的自适应分区、异构调度

核心问题：能否把布线任务组织成适合片上工作集的批次，在减少搬运和存储冲突的同时保持足够并行度？

DFMAcc 的分区模型可以把几何密度替换为预估扩展边数、活跃状态量、节点更新冲突、跨区资源数量和传输量；AccDRC 的两级任务封装可以对应“区域批次—连接/网络—候选更新”。结合上一轮统计或预算内试跑动态调整任务粒度，无需首先引入学习模型。

调度目标可从最少任务时间扩展为最小总完成时间：一个稍慢的搜索若复用已驻留图页，可能比重新加载其他区域更划算。CPU、GPU、FPGA 的划分可参考连接规模、前沿宽度、依赖深度、复用程度与当前队列。已有 GPU 的卸载阈值不能直接当作 FPGA 阈值；FPGA 对中等规模高频任务的收益也值得测量。

边界处理是迁移的关键：静态数据可复制，动态资源由规范节点 ID 统一管理；跨区路径通过边界端口继续搜索。固定 halo 不能保证覆盖所有绕行，区域包围盒不交也不必然意味着长线物理资源不共享。需要资源层面的所有权、版本或冲突检测，必要时扩大区域或回退完整搜索。

最小实验：固定区域划分、已有三叉树/DAG 调度、按估计工作量分区、加上驻留复用的调度逐级对照。测量 PE 空闲、搬运、尾部任务、状态页命中、重搜及总协商轮数。PathFinder 中间允许资源超额，不能把所有中间共享都当作必须拒绝的非法冲突。

可实现性：软件调度原型较容易；边界一致性与硬件实现中等偏难。这条路线也可独立作为系统论文主线。

D．可变出度搜索的事件驱动数据流与优先级组织

核心问题：能否以较少无效扩展和较高流水利用率，推进真实 FPGA 资源图中的优先级搜索？

借鉴 FlowGNN、ThunderGP 与 Sextans，把候选读取、邻接生成、代价计算、按目标节点合并更新和再入队拆成流式模块；用动态队列处理不同出度，用多连接上下文隐藏单连接依赖。RouterAcc 的代价与分层存储经验可复用，六邻居输入和坐标寻址则需要改造。

候选结构可以比较精确优先队列、分桶队列和有限批量扩展，不预先规定唯一选择。当前源码的地址区间扫描提供了一个工程参照，但不能用修复原型扫描问题代替与已有硬件队列的比较；2019 年 FPGA 辅助布线工作已使用硬件优先队列。

最小实验：相同冻结代价下比较节点扩展数、成功松弛数、更新冲突、队列操作量与完整路径时间；随后接入外层协商。并行松弛必须处理同节点在途更新，必要时重新打开节点；停止判据应考虑在途工作，不能“目标第一次入队即结束”。若使用近似顺序，应明确其质量目标，而非默认保留最短路最优性。

可实现性：中等。决定收益的是有效更新与完整搜索的吞吐，单个算术模块达到 II=1 并不能证明整个搜索每拍推进。

E．FPGA 加速异构约束布局的候选评估或数值内核

核心问题：布局的哪些高频计算能够形成连续、可复用的数据流，并在完整布局布线质量受控的条件下缩短运行时间？

可以从两种最小实现任选其一。其一，在现有布局器中批量计算移动/交换候选的增量线长、拥塞、延迟估计以及资源类型/区域约束；CPU 处理接受决策及复杂合法化。其二，迁移 FBLAS/Sextans 的方法，加速解析布局中的稀疏 pin/net 聚合、平滑线长代价及梯度、密度数据更新与位置更新。两种路径都可以逐步扩大硬件范围。

对 DSP、BRAM、级联宏与区域约束，可设计按资源类别和合法候选位置组织的数据通路。批量候选共享网表和位置快照，只传送差量，适合研究驻留状态、稀疏更新和候选选择。重叠移动不能未经检查同时提交；解析布局密度模型的全局求解部分也应按所选算法单独分析。

直接参考包括 FPGA 2026 硬件 page placement，其仓库提供行为仿真、RTL 与实卡流程；复杂宏约束可参考 DREAMPlaceFPGA-MP。两者适用任务不同，不能把 page 放置性能直接视为完整商业 FPGA 布局的可比结果。

最小实验：保持同一布局器的外层策略，替换一个候选评估或数值阶段，比较软件与硬件完整布局时间，并执行后续布线检查时序、线长、拥塞与成功率。若仅局部加速，应通过实际阶段占比评估端到端价值。

可实现性：候选评估中等；完整解析布局数据流中等偏难。当前已有代码对布线支持更强，但这只是开发成本差别，不是排除布局创新的理由。

F．硬件局部布线评估驱动的布局—布线反馈

核心问题：能否把真实资源图上的局部布线评估做得足够便宜，使布局过程更频繁地获得有用反馈，并减少后期失败或返工？

迁移 DFMAcc 的粗过滤—精验证：先用线长、资源密度或已有预测器筛选布局候选，再对有价值或不确定的候选执行硬件局部重布线。输入包括候选移动、受影响网络、外部路径接口、当前占用/价格快照；输出可以包括局部连通结果、超额资源、绕行代价、延迟变化和消耗的搜索预算。

多个候选共享图和未改动状态，通过影子状态或差量页隔离试探结果；确定接受的候选才更新权威设计状态。局部搜索失败只能说明当前边界和预算下未找到路径，不能直接证明全局不可布；局部成功也不能自动证明整设计可布。

最小实验：同一布局器比较不使用反馈、廉价拥塞估计、CPU 局部真实布线、FPGA 同算法局部布线。必须加入相同总时间预算的比较，观察硬件是否能支持更多有效候选，最终缩短布局加布线总时间或改善同时间预算下的质量。

可实现性：中等偏难。它可充分复用前四条路线的引擎，同时把应用价值落到布局决策；无需先完成一个全新的全芯片布局器。

G．面向多 die / 三维 FPGA 的跨层资源选择与分层搜索

核心问题：当跨层或跨 die 资源成为瓶颈时，能否联合选择连接资源和局部路径，并用 FPGA 并行评估候选来降低总体求解成本？

借鉴 H3D 的异构资源建模与树上动态规划，把状态改写为“层/区域—可用垂直端口—分支连接关系”；在真实 RRG 允许的端口集合上选择，结合拥塞价格与时序代价。硬件可以批量评估端口组合、执行局部搜索和归约候选，软件完成全局协商与树更新。

可选两个实验对象：商业多 SLR 器件中工具公开的跨区资源；或 LaZagna 的可控三维架构。后者支持垂直互连模式、层异构与跨层延迟参数，适合扫描不同场景。针对三维布局，还应比较 Escaping Flatland 的层分配、代价调节与移动策略。

最小实验：先用 CPU 在固定三维 RRG 上建立“原路由器—简单跨层代价—候选端口选择”对照，再对同一个候选算法做 FPGA 加速。分别扫描垂直资源密度、延迟、层数和网络扇出，报告全局合法性、时序、线长及跨层资源使用。减少跨层数量不必然改善时序，应让模型和实验决定。

可实现性：模型化架构的软件算法验证中等，完整硬件协同偏难。普通加速卡即可处理三维图，实验结论限定于对应架构模型；无需把真实三维工艺提取作为前置条件。

共同实验底座与逐步扩展方式

为了同时保留多个研究方向，先统一任务、状态与结果接口。初版沿用同学代码的单连接或连接批次卸载边界，类似 gpuFloodConnection 的调用层次；CPU 执行外层协商和路径提交，FPGA 完成一次完整搜索并返回路径。避免每扩展一个节点都通过 PCIe 往返。

硬件接口宜保留：规范资源 ID、任务/上下文 ID、代价版本、源与候选目标、同网共享信息、搜索边界、预算与回退状态。先保持软件基线的代价语义，再引入量化或近似搜索，才能分离算法变化和硬件变化。

正确性需覆盖：可编程连接与方向、受保护资源、同网多分支共享、路径回溯、状态隔离和最终容量约束。资源占用按不同 net 计数，同网连接需要引用关系；中间过容量与最终非法应区别处理。低精度路径重新计价可以验证该路径的代价，不能单凭这一项证明搜索没有错过更优候选。

板卡选择：优先方便公平对照

建议首选 Alveo U280，作为同卡 DDR/HBM 对照平台。官方平台提供 32 GB DDR、8 GB HBM 和 32 个 HBM 伪通道；因此可在同一器件上比较 DDR、HBM 与混合层次。Sextans 等参考实现也使用 U280，有利于复用存储与数据流经验。依据：AMD U280 平台文档。

相同数据集、相同 PE 数和片上缓存预算、相同目标频率下，比较存储后端；同时披露实现后频率、内存通道映射和物理布局。DDR/HBM 接口与位置仍存在差异，因此同卡实验减少了器件差异，但并未自动消除所有变量。超过共同容量的数据集另外报告容量可扩展性。

U250 可作为已有条件下的 DDR 可移植性验证，但不必为了首篇论文额外增加一张卡。它的逻辑资源和存储配置不同，不应把 U250 对 U280 的时间差直接解释为 HBM 的收益。FPGA 2026 page placer 的原仓库使用 VCK190 ES1 与 2021.2 工具；可以借鉴其算法和复现流程，移植到 U280仍需适配。

本机已检查到 Vivado、Vitis、Vitis HLS 2022.2 可执行文件。尚未检查实体板卡、平台安装包与 XRT 驱动组合，故不把“工具路径存在”当作“实卡环境已就绪”。板卡建议基于实验结构，不代表当前采购供应或已获得设备。

系统贡献已有 CPU/GPU 流程、新 CPU+FPGA 流程、必要时异构组合传输、预处理、回退和协商轮数计入后，是否仍有收益？
质量与能力相同约束下完整布局布线；困难和失败案例也纳入报告是否保持合法性、时序与线长，是否提高可处理规模或等预算质量？

路由基线至少包含同学现有的优化 C++ 与 GPU 配置。外部比较可加入 Potter等公开路由器，但要统一器件、输入格式、约束和计时口径；其默认目标与同学的 xcvu13p 环境不同，不能直接引用各自报告的倍数。布局比较采用匹配问题范围的 VPR、DREAMPlaceFPGA 系列或宏布局器。

计时从数据准备、首次构图、上传、初始化、搜索、回溯、提交、价格更新、回退到最终输出完整分解；分别报告首次运行与驻留复用运行。完整布局研究使用布局加布线总时间。能耗若作为主张，应明确测量的是卡级还是主机与设备总能耗。

机制指标包括：每次成功松弛的访问字节、节点扩展数、OPEN 峰值、状态页利用率、初始化时间、在途冲突、PE 空闲、任务尾时延、重搜和协商轮数。GPU/FPGA 内核速度与端到端速度分别报告，不能与其他配置的预处理或迭代数据拼接。

当前代码以非时序驱动路径为重要基础；线长相近不能代替时序相近。第一阶段可以明确研究非时序驱动布线加速，并补充布后时序；若论文主张时序驱动优化，则需要实现并验证相应代价与关键性机制。

消融可以围绕单项主贡献设计，或采用小规模交叉实验，例如“压缩开/关 × 驻留开/关 × DDR/HBM”。无需穷举所有组合；选择能够回答主假设和相互作用的实验，并公开无收益与回退情况。

建议的研究组织与推进顺序

候选论文组织可选主贡献最容易利用的现有基础
面向商业 FPGA 布线的结构化资源表示与驻留搜索加速A、B、C、D 中任一项为主，其余提供支撑；根据实验决定标题中心。同学 CPU/GPU 框架与器件模板；RouterAcc 硬件经验。
面向异构约束布局的批量候选评估与 FPGA 加速E 的候选评估或解析布局内核。公开布局器与流式稀疏算子方法；已有资源模型。
基于硬件局部布线评估的布局—布线反馈优化F 的反馈机制、候选复用或预算分配。可复用的搜索引擎、布局器插件与局部状态管理。
面向三维 FPGA 的跨层资源选择与异构加速G 的端口选择、树优化或分层并行执行。LaZagna/VTR、H3D 方法和前述图搜索引擎。

开发顺序建议先做共享底座，原因是它能降低多个方向的试验成本。第一步固定代码配置并复现 CPU/GPU 小、中、大代表实例；第二步采集真实搜索、状态和资源访问轨迹，同时选择一个布局候选评估入口；第三步以软件验证压缩展开、稀疏状态与分区方案；第四步实现单连接/批次 FPGA 引擎；第五步将有效机制接回完整流程，决定哪条路线具备最清楚的主贡献。

决策依据应来自实测：若字节搬运占主导，深入 A；若短搜索的大量初始化和重复准备占主导，深入 B；若尾部任务与区域失衡严重，深入 C；若队列反馈或无效扩展突出，深入 D；若布局阶段占比或候选约束计算突出，深入 E；若后期布线返工严重，深入 F；若跨 die 资源竞争主导，深入 G。也可能出现两个机制必须联合才能获得收益，此时可以把协同关系作为研究问题。

这些判断用于安排投入，不用于预先宣布其他方向缺乏创新。成熟方法提供可实现的起点；论文贡献最终由具体机制、相对已有工作的差异、受控实验和适用边界共同支撑。

本报告未修改现有算法或 RTL，未将参考论文的加速比视为本方案的性能预测。公开资料核对截至分析日期，文献检索并非穷尽；各候选的最终新颖性仍需围绕确定的实现与最接近工作进一步比较。
