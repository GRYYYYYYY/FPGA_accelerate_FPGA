# 方案 F 继续研究入口

当前已具备目录、配置、实验计划和可运行合成参考。建议下一次会话先运行 `python3 scripts/run.py check` 与 `python3 scripts/run.py smoke`，再开展下面的第一项实质工作。

1. 实现 CPU 局部评估器和条件化结果，先确认反馈能影响布局结果，再迁移硬件。
2. 以 D 的完整连接接口为起点，增加局部边界、候选上下文和预算；布局入口由 E 或现有布局器提供。
3. 把真实数据接入 `adapters/`，记录版本、字段映射、哈希与必要的语义检查。
4. 复现 [EXPERIMENTS.md](EXPERIMENTS.md) 中最接近的基线，然后选择一个具体迁移机制。
5. 候选初筛 → 批量局部布线 → 反馈排序/接受 → 权威状态提交 → 最终完整布线。
6. 根据实测热点决定硬件范围：复用 D 的搜索引擎，增加共享快照、候选差量页、预算计数和结果归约。

可以直接给下一次助手的任务描述：

> 在方案 F 目录继续研究“硬件局部布线评估驱动布局反馈”。先阅读 AGENTS.md、README.md、EXPERIMENTS.md 和 NEXT_STEPS.md，保留其他方案目录及原始参考代码。当前只有 CPU 合成样例，不要把它当作真实基准。优先完成：实现 CPU 局部评估器和条件化结果，先确认反馈能影响布局结果，再迁移硬件。 对方法迁移保持开放，依据具体机制与实验判断贡献。
